# OpenShiksha Daily Plan — 2026-05-20

> **Context**: The May 7th plan (teacher question bank, student SRS panel, parent dashboard) was fully implemented and merged in PR #79. Today builds on that foundation: the parent dashboard shows proficiency but nothing about assignments; proficiency has no history so progress over time is invisible; and the entire frontend is desktop-first despite India's student population being primarily mobile.

---

## A. Today's Objective

Give students and parents a sense of **progress over time** (proficiency trend snapshots), make the parent dashboard actually useful for daily homework monitoring (assignment status view), and make the student experience work on mobile (responsive pass on the three most-used pages).

---

## B. Why This Matters

- **Proficiency Trend Snapshots**: The current proficiency page shows a single score — today's number. There is no way to see whether a student is improving or declining. `StudentProficiency.updated_at` changes on every grading cycle but the old score is discarded. Adding `StudentProficiencySnapshot` (a lightweight append-only record written each time proficiency updates) unlocks trend lines for students, parents, and future teacher analytics. This is the insight that answers "Am I getting better?" — the most motivating question in self-directed learning.

- **Parent Assignment View**: The parent dashboard (new as of May 7) shows proficiency bars. But parents ask a simpler question every evening: "Did my child do their homework?" The platform has a full `Assignment` model with `due_at`, `submission_count`, and per-student `Submission` records — everything needed to show a parent whether their child has submitted, is overdue, or has an upcoming deadline. This extends the parent dashboard with its most practical feature.

- **Mobile-First Responsive Pass**: All current Tailwind classes assume a desktop viewport. The Navbar shows full nav links inline at all widths. The student dashboard, assignment card list, and proficiency page use no responsive breakpoints beyond `max-w-2xl`. India's student demographic skews heavily mobile. A targeted responsive pass on the three highest-traffic student pages — dashboard, assignment detail, and the Navbar — removes the biggest UX friction for actual users.

#### Step 1 — New `StudentProficiencySnapshot` model

**File**: `backend/openshiksha/apps/edge/models.py`

Add after the `StudentProficiency` class:

```python
class StudentProficiencySnapshot(models.Model):
    """
    Append-only record written every time StudentProficiency is recalculated.

    Design:
    - Never updated — always inserted. Preserves full history.
    - Keyed on (student, question_tag, subject_room) so queries are simple.
    - No ForeignKey to StudentProficiency to keep it independent (snapshot
      survives even if the live record is deleted).
    - recorded_at uses auto_now_add for immutability.

    Usage:
    - Trend chart: filter(student=s, question_tag=t, subject_room=r).order_by('recorded_at')
    - Progress over N days: filter(..., recorded_at__gte=cutoff)
    """

    student = models.ForeignKey(
        "core.User",
        on_delete=models.CASCADE,
        related_name="proficiency_snapshots",
    )
    question_tag = models.ForeignKey(
        "core.QuestionTag",
        on_delete=models.CASCADE,
        related_name="proficiency_snapshots",
    )
    subject_room = models.ForeignKey(
        "core.SubjectRoom",
        on_delete=models.CASCADE,
        related_name="proficiency_snapshots",
    )
    score = models.FloatField(help_text="Snapshot of score at this point in time (0.0–1.0)")
    recorded_at = models.DateTimeField(auto_now_add=True, db_index=True)

    class Meta:
        ordering = ["recorded_at"]
        indexes = [
            models.Index(fields=["student", "question_tag", "subject_room", "recorded_at"]),
        ]

    def __str__(self):
        return f"Snapshot({self.student_id}, {self.question_tag_id}, score={self.score:.2f}, at={self.recorded_at.date()})"
```

**Why append-only?** Snapshots are written but never updated. This ensures the full trend history is always available — even if a student is moved to a new classroom, the old trend data is preserved.

```python
from openshiksha.apps.edge.models import StudentProficiencySnapshot

@action(detail=False, methods=["get"], url_path="history")
def history(self, request):
    """
    GET /api/proficiency/history/?tag=<id>&subject_room=<id>
    Returns snapshot history for the current student (or child if parent).
    """
    tag_id = request.query_params.get("tag")
    room_id = request.query_params.get("subject_room")
    if not tag_id or not room_id:
        return Response({"detail": "tag and subject_room are required."}, status=400)

    user = request.user

    if user.role in (UserRole.STUDENT, UserRole.OPEN_STUDENT):
        student_id = user.id
    elif user.role == UserRole.PARENT:
        child_id = request.query_params.get("student")
        if not child_id:
            return Response({"detail": "student is required for parent role."}, status=400)
        try:
            child_pk = int(child_id)
        except (ValueError, TypeError):
            return Response([], status=200)
        if not user.children.filter(id=child_pk).exists():
            return Response([], status=200)
        student_id = child_pk
    else:
        return Response([], status=200)

    snapshots = (
        StudentProficiencySnapshot.objects.filter(
            student_id=student_id,
            question_tag_id=tag_id,
            subject_room_id=room_id,
        )
        .order_by("recorded_at")
        .only("id", "score", "recorded_at")
    )
    return Response(StudentProficiencySnapshotSerializer(snapshots, many=True).data)
```

Register in `urls.py` — the `history` action auto-registers as `GET /api/proficiency/history/` because it's on the `StudentProficiencyViewSet`.

**New file**: `frontend_modern/src/features/student/useProficiencyHistory.ts`

```typescript
import { useQuery } from '@tanstack/react-query';
import { apiClient } from '@/api/client';

export interface ProficiencySnapshot {
  id: number;
  score: number;
  recorded_at: string;  // ISO datetime
}

interface HistoryParams {
  tagId: number;
  subjectRoomId: number;
  studentId?: number;  // for parent role
}

const fetchHistory = async (params: HistoryParams): Promise<ProficiencySnapshot[]> => {
  const searchParams = new URLSearchParams({
    tag: String(params.tagId),
    subject_room: String(params.subjectRoomId),
  });
  if (params.studentId) searchParams.set('student', String(params.studentId));
  const { data } = await apiClient.get<ProficiencySnapshot[]>(
    `/proficiency/history/?${searchParams}`
  );
  return Array.isArray(data) ? data : [];
};

export const useProficiencyHistory = (params: HistoryParams | null) =>
  useQuery<ProficiencySnapshot[]>({
    queryKey: ['proficiency', 'history', params],
    queryFn: () => fetchHistory(params!),
    enabled: !!params,
    staleTime: 5 * 60 * 1000,
  });
```

#### Step 6 — `TrendSparkline` component

**New file**: `frontend_modern/src/shared/components/TrendSparkline.tsx`

A minimal CSS-only sparkline (no external charting library — no new dep):

```tsx
import type { ProficiencySnapshot } from '@/features/student/useProficiencyHistory';

interface Props {
  snapshots: ProficiencySnapshot[];
  width?: number;
  height?: number;
}

export const TrendSparkline = ({ snapshots, width = 80, height = 24 }: Props) => {
  if (snapshots.length < 2) return null;

  const scores = snapshots.map((s) => s.score);
  const min = Math.min(...scores);
  const max = Math.max(...scores);
  const range = max - min || 0.01;  // avoid division by zero

  const points = scores.map((score, i) => {
    const x = (i / (scores.length - 1)) * width;
    const y = height - ((score - min) / range) * height;
    return `${x.toFixed(1)},${y.toFixed(1)}`;
  }).join(' ');

  const lastScore = scores[scores.length - 1];
  const firstScore = scores[0];
  const trend = lastScore - firstScore;
  const color = trend > 0.01 ? '#22c55e' : trend < -0.01 ? '#ef4444' : '#94a3b8';

  return (
    <svg
      width={width}
      height={height}
      viewBox={`0 0 ${width} ${height}`}
      className="inline-block"
      aria-hidden="true"
    >
      <polyline
        points={points}
        fill="none"
        stroke={color}
        strokeWidth="1.5"
        strokeLinecap="round"
        strokeLinejoin="round"
      />
    </svg>
  );
};
```

No external charting lib needed. SVG polyline with green/red/neutral color based on trend direction.

```python
def get_queryset(self):
    if getattr(self, "swagger_fake_view", False):
        return Assignment.objects.none()
    user = self.request.user
    qs = Assignment.objects.select_related(
        "problem_set__subject",
        "problem_set__chapter",
        "subject_room__classroom",
        "subject_room__subject",
        "assigned_by",
    ).prefetch_related(
        "problem_set__questions__subparts__tags",
        "problem_set__questions__tags",
    )

    if user.role in [UserRole.STUDENT, UserRole.OPEN_STUDENT]:
        return qs.filter(subject_room__students=user, subject_room__is_active=True)
    elif user.role == UserRole.TEACHER:
        return qs.filter(assigned_by=user)
    elif user.role == UserRole.ADMIN:
        return qs.filter(subject_room__classroom__school=user.school)
    elif user.role == UserRole.PARENT:
        child_id = self.request.query_params.get("student")
        if not child_id:
            return qs.none()
        try:
            child_pk = int(child_id)
        except (ValueError, TypeError):
            return qs.none()
        if not user.children.filter(id=child_pk).exists():
            return qs.none()
        # Return assignments in subject rooms where the child is a student
        return qs.filter(
            subject_room__students__id=child_pk,
            subject_room__is_active=True,
        )
    return qs.none()
```

#### Step 2 — Backend: Add `child_submission_status` annotation to `AssignmentSerializer`

**File**: `backend/openshiksha/apps/api/serializers/core.py`

Parents need to know whether their child specifically submitted — not the class aggregate. Add a method field to `AssignmentSerializer`:

```python
class AssignmentSerializer(serializers.ModelSerializer):
    # ... existing fields ...
    child_submission_status = serializers.SerializerMethodField()

    class Meta:
        model = Assignment
        fields = [
            # ... existing fields ...
            "child_submission_status",
        ]

    def get_child_submission_status(self, obj) -> str | None:
        """
        If the requesting user is a parent and ?student=<id> is provided,
        return the child's submission status: 'submitted', 'not_submitted', or None.
        """
        request = self.context.get("request")
        if not request:
            return None
        user = request.user
        if user.role != UserRole.PARENT:
            return None
        child_id = request.query_params.get("student")
        if not child_id:
            return None
        try:
            child_pk = int(child_id)
        except (ValueError, TypeError):
            return None
        has_submission = obj.submissions.filter(student_id=child_pk).exists()
        return "submitted" if has_submission else "not_submitted"
```

This makes the assignment list response self-contained for parents — no second API call needed to check submission status.

## F. Legacy Analysis & Improvement Opportunities

### Proficiency Trend (Priority 1)

**Legacy**: No trend tracking. `edge/models.py` in legacy had a `StudentProficiency` model with a `score` field that was overwritten on every calculation. No snapshot, no history, no chart.

**Modern improvement**: Append-only `StudentProficiencySnapshot` created every time proficiency is recalculated. This turns the proficiency model into a time series for free. The SVG sparkline adds visual trend at zero external dependency cost. Future: aggregate weekly/monthly averages for longer-term trend views; feed into `PerformancePrediction` AI model for forecasting.

### Parent Engagement (Priority 2)

**Legacy**: Parents received only SMS notifications via Pylon. No web interface, no drill-down, no assignment status visibility.

**Modern improvement**: Phase 1 (May 7) — proficiency bars. Phase 2 (today) — assignment status view. Together these give parents both the "how well are they doing?" (proficiency) and "are they keeping up?" (assignments) answers in one place. Future: push notifications when new assignments are created or when child submits.

### Mobile Experience (Priority 3)

**Legacy**: Desktop-only Django template UI. No mobile consideration.

**Modern improvement**: React + Tailwind makes responsive design mechanical. The Navbar hamburger pattern and `sm:` responsive classes are a small change with outsized UX impact. India's internet access is predominantly mobile — students in rural/semi-urban areas may have no desktop at all. Making the student experience work at 375px removes a real access barrier.
