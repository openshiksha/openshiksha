## A. Today's objective

Close the **last open surfaces** of Accessibility Batch 3 — the dense teacher
**authoring forms** (`CreateQuestionPage`, `CreateAssignmentPage`,
`CreateProblemSetPage`) and the **parent insights** pages — by running them
through the same **baseline → remediate → gate** loop the rest of the app already

## B. Why this matters

Today the measured-and-gated AA contract covers the public front door, the
student core loop, and the teacher/parent **core** surfaces (#442/#450/#452).
The only authenticated surfaces still **unmeasured** are exactly the ones a
teacher spends the most keyboard time in — the multi-field authoring forms — and
the parent's deep-dive insights pages. These are the densest, most
input-heavy screens in the app, so they're where label/fieldset/contrast gaps
are most likely and most costly. Gating them turns the last "we think it's fine"
surfaces into "CI proves it's fine." Batch 4 then begins converting the two
remaining **manual** DoD promises (keyboard-only + screen-reader) into
repeatable, partly-automated evidence — the difference between an a11y
*aspiration* and an a11y *contract*, which is this initiative's North Star.

  ```ts
  { name: 'parent-insights-child',     path: '/parent/insights/10',        gate: false, auth: 'parent' },
  ```
  (Child id `10` matches `CHILD_USER.id` already in `auth.ts`.)
- **Fixtures** in
  [`frontend_modern/e2e/support/auth.ts`](../../frontend_modern/e2e/support/auth.ts):
  the `makeRouteHandler` catch-all already returns an empty paginated page for
  unknown list reads, so the forms will render their empty/selectable states.
  Add only the **object reads** these pages need that 404/empty would break:
  - `CreateAssignmentPage` / `CreateProblemSetPage`: subject-rooms, standards,
    subjects, chapters, problem-sets selectors — confirm each renders from the
    empty-paginated default; add a tiny non-empty fixture **only** where an empty
    list hides the form fields axe must scan (a select with zero options still
    renders a labelled control, which is enough — prefer the empty default).
  - `parent/insights` + `/insights/:childId`: stub `/users/me/children/` (exists)
    and any per-child proficiency/summary object read with a minimal body so the
    page renders past its loading state to a visible `h1`.
- **How to verify:** `cd frontend_modern && npx playwright test e2e/a11y.spec.ts`
  → the five new `axe-report/<name>.json` files exist and each test passes
  (reporting-mode never fails). Inspect each JSON's `summary.blocking` to author
  A11Y-14's fix list.
- **What could go wrong:** a form gated behind a required selection may never show
  its inner controls under empty fixtures — if so, seed a one-row fixture for that
  selector. The dense forms may not render an `h1` quickly → the
  `expect(h1).toBeVisible()` settle step covers it, but confirm each page actually
  has an `h1` (add one in A11Y-14 if a form leads with an `h2`, which is itself a
  heading-order finding worth fixing).

### A11Y-14 — Remediate the baseline findings

- **Likely findings** (to confirm against A11Y-13's JSON, not assume):
  - **Unlabelled inputs** — `auth.ts` already flags that numeric/fill-blank
    render a bare `<input>` named only by placeholder; the authoring forms have
    many such free inputs (variable-constraint min/max, option text, marks).
    Fix: associate every control with a `<label htmlFor>` or `aria-label`; the
    existing LA i18n registry supplies localized label strings.
  - **Grouping** — radio/checkbox clusters (question type, difficulty pills,
    subpart kind) need `fieldset`/`legend` or `role=radiogroup` + `aria-label`.
  - **Heading order** — a form leading with `h2`/`h3` under no `h1` trips
    `page-has-heading-one`/`heading-order`; give each page a single `h1`.
  - **Contrast** — reuse the A11Y-11 rule: small brand text on `brand-50` tint →
    `brand-800`; difficulty/status pills checked ≥ 4.5:1.
- **Scope discipline:** structural + contrast only (the gating axe rules). Defer
  visual redesign. Mirror the A11Y-7/A11Y-11 precedent: minimal token/markup
  changes, hierarchy by weight not opacity.
- **Tests:** extend the existing Vitest files for each touched component
  (`CreateQuestionPage.test.tsx` etc.) to assert the new accessible names /
  `getByRole('radiogroup')` / single `h1`. Re-run the A11Y-13 baseline locally to
  confirm `summary.blocking` shrank to `[]` on each route.
- **What could go wrong:** adding `fieldset` can disturb the form's flex/grid
  layout (`fieldset` has UA default styling) — reset with `border-0 p-0 m-0
  min-w-0` Tailwind utilities, and verify the mobile (RML-3) layout still holds.

### A11Y-16 — Automated keyboard-traversal spec (Batch 4 kickoff)

- New `frontend_modern/e2e/keyboard.spec.ts` reusing `AUTH_SETUP.student`:
  - **Skip link:** load `/student`, press `Tab` once, assert focus is the skip
    link, `Enter`, assert `document.activeElement` is within `#main-content`.
  - **No keyboard trap:** Tab N times across `/student/assignments/1`, assert
    focus advances and eventually leaves each control (WCAG 2.1.2).
  - **Dialog focus-trap + Escape:** open the QuestionBank side-sheet (the M6-01
    dialog), assert focus moves into it, Tab cycles **within** it, `Escape`
    closes it and returns focus to the trigger (WCAG 2.4.3 / 2.1.2).
- **Verify:** `npx playwright test e2e/keyboard.spec.ts` green; add it to the
  `frontend-e2e` CI job (same runner as `a11y.spec.ts`).
- **What could go wrong:** focus assertions are timing-sensitive — use Playwright
  `expect.poll`/`toBeFocused` rather than a single snapshot; the
  no-`allow-same-origin` sandbox can't be focus-introspected from the parent
  (DTB-4 lesson) — keep the dialog assertions on app DOM, not iframe internals.

### A11Y-17 — Screen-reader sign-off scaffold + announce-region audit

- New `docs/initiatives/a11y/screen-reader-signoff.md`: a per-journey NVDA
  (Windows) + VoiceOver (mac/iOS) script — sign-in, register, browse, **practice
  + submit**, parent dashboard — each step listing the expected announcement, a
  pass/fail column, and the tester/date. This is the **DoD item 5** evidence
  template (manual, run by a human; the doc is the deliverable today).
- **Announce-region audit (the automatable slice):** grep the dynamic regions —
  assignment auto-save status, grade reveal, toast/notification, the
  "Saved offline · will sync" banner (MSO-8) — and ensure each has the right
  live-region semantics (`role=status`/`aria-live="polite"` for status,
  `aria-live="assertive"` only for errors). Add `getByRole('status')` assertions
  to the relevant Vitest files.
- **Verify:** Vitest green for the announce-region assertions; the sign-off doc
  renders on GitHub with a clean per-journey table.
- **What could go wrong:** over-announcing — don't wrap the whole form in
  `aria-live`; scope it to the single status node, or screen readers flood the
  user on every keystroke.

## F. Legacy analysis & improvement opportunities

There is **nothing to port** — legacy Django 1.11 templates had no ARIA, no
contrast discipline, no automated a11y checking whatsoever. Every item here is
**net-new platform capability**. The improvement lens:

- **Authoring forms:** legacy `sphinx/` authoring was a raw HTML form dump with
  no labels-for, no grouping, no keyboard story. The modern rebuild already has
  React-controlled inputs; A11Y-14 makes them *named and grouped* — a strict
  upgrade a screen-reader user can actually operate.
- **Keyboard/SR contract:** legacy had no concept of a measured a11y gate.
  A11Y-16/17 introduce the *evidence* (automated traversal + a repeatable manual
  script) that turns "accessible by default" (V2 principle #7) from a slogan into
  a checkable artifact.
