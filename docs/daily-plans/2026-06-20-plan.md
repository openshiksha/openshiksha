## B. Why this matters

- **Finishes the public contrast story and unblocks every gate downstream.** The
  brand button is the primary CTA on *every* screen; until its enabled state
  clears 4.5 : 1 we cannot gate `/` (home) or any authenticated surface that uses
  `.btn-brand`. A11Y-4 is the keystone — it was correctly deferred as a *design*
  decision in Batch 1, and this plan makes that decision concretely (below) so the
  execute agent can ship it mechanically.
- **The student core loop is where students live.** K-12 students on budget Android
  phones, some low-vision or keyboard-only, spend almost all their time on the
  dashboard → assignment → submit → proficiency loop. Batch 1 gated the *front
  door*; this batch gates the *house*. That is DoD item 4 — the heart of the
  initiative.
- **Keyboard access is half of WCAG.** axe can't see focus order or focus-visible;
  a deliberate focus-indicator pass on the shared interactive primitives is the
  cheapest, highest-leverage keyboard win and is reusable everywhere (DoD item 5
  down-payment).
- **Lowest-risk, compounding, mostly frontend.** No backend schema change. The
  contrast fix is token-usage only; focus-visible is CSS on shared primitives; the
  authenticated harness reuses the Batch-1 per-route axe table and the existing
  Playwright `frontend-e2e` CI job. Each PR is independently shippable behind the
  CI guards.

## D. Concrete implementation plan

### A11Y-4 — Brand-shade decision + contrast sweep + re-gate `/` *(Improve, build first)*

**The design decision (made here so the execute agent ships it mechanically):**
Preserve `#FF6F00` (`brand-600`) as the **decorative / large-element anchor** —
logo, `chalk-underline`, large hero numerals, borders, focus rings, big badges —
where WCAG only requires 3 : 1 (large/non-text) or nothing (decoration). For
**white-text-on-brand fills and small brand-text-on-paper**, adopt a **darker
on-text shade that clears 4.5 : 1**. Concretely:

- In `tailwind.config.js`, retune **`brand-700` from `#CC5800` (≈ 4.2 : 1) to
  `#C05300`** (≈ 4.7 : 1 with white — verified). `brand-700` today is used only
  for hovers/text accents, so darkening it slightly is safe and *improves*
  contrast everywhere it appears. `brand-800 #9E4500` (≈ 6.1 : 1) stays the hover
  target.
- In `src/index.css`:
  - `.btn-brand`: `bg-brand-600` → **`bg-brand-700`**, `hover:bg-brand-700` →
    **`hover:bg-brand-800`**. (Disabled stays `brand-300`.)
  - `.prose-osh a` and the link helper at `index.css:125`: `text-brand-600` →
    **`text-brand-700`** for small body/link text (large display brand text may
    stay `brand-600`).
- Sweep `text-brand-600` used as **small** body/label/link text across
  `src/features/**` and `src/shared/ui/**` → `text-brand-700`. Leave `text-brand-600`
  on large headings/numerals (≥ 24 px or ≥ 19 px bold → 3 : 1 suffices). Grep:
  `grep -rn "text-brand-600" src/`.
- **Document** a short "Contrast rules" subsection in
  `docs/initiatives/2026-design-system-v2.md` (or the a11y initiative doc):
  *`brand-600` = decorative/large only; `brand-700` = the on-text/CTA brand shade
  (≥ 4.5 : 1 white & on-paper); never put `text-white` on `brand-600` for text.*
- In `e2e/a11y.spec.ts`, flip **`home` (`/`) to `gate: true`** — the enabled hero
  `.btn-brand` now passes, so its contrast no longer hides in `incomplete`.

**Verify.** `npx playwright test a11y` (the `/` route now asserts `blocking === []`);
eyeball `/design` and the hero for no visual regression; `npm run build` (no
runtime impact). Spot-check the new CTA contrast with a ratio tool (`#C05300` on
white-text ≥ 4.5 : 1).

**What could go wrong.** Darkening `.btn-brand` mutes the vivid orange — keep it to
`brand-700`, not `brand-800`, so the CTA stays lively while passing. If retuning
`brand-700` shifts a hover or accent unexpectedly, prefer adjusting the *usage*
(point `.btn-brand` hover at `brand-800`) over re-tuning twice. Don't introduce a
new colour outside the brand family.

### A11Y-FV — Keyboard focus-visible indicator pass *(Improve, independent)*

**Frontend.** Ensure every focusable control shows a clear, consistent
`:focus-visible` ring (WCAG 2.4.7 Focus Visible, 2.1.1 Keyboard):

- Add a shared focus-ring utility/token in `src/index.css` —
  `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand-500
  focus-visible:ring-offset-2 focus-visible:ring-offset-paper` (use the existing
  paper bg token). Apply it to `.btn-brand`, `.btn-ghost`, `.input-brand`, and any
  bare `<a>`/`<button>`/tab/nav primitives in `src/shared/ui/**` that lack a
  visible focus state.
- Audit the bottom-tab bar / account drawer / skip-link (M5/M6 chrome) and the
  assignment-detail answer controls for a visible focus ring. Prefer
  `:focus-visible` (not `:focus`) so mouse clicks don't show the ring.
- Respect the existing reduced-motion block already in `index.css`.

**Verify.** Manual keyboard walkthrough: Tab through `/login`, `/student`, an
assignment — every stop shows a visible ring, tab order is logical, no focus trap.
`npm run build`; `npx vitest run`. Capture the walkthrough in the A11Y-8 checklist.

**What could go wrong.** A global `*:focus-visible` rule can double-ring controls
that already style focus — scope to the shared primitives and the known-bare
elements, don't blanket-apply. Keep the ring inside the V2 palette (`brand-500`).

### A11Y-6 — Authenticated axe harness + student core-loop baseline *(New, build third)*

**Frontend (test harness).** The `frontend-e2e` CI job runs the Vite preview with
**no backend**, so authenticated routes need a stubbed session, not a live login:

- Add a Playwright helper `e2e/support/auth.ts` that, before navigation:
  1. seeds `localStorage` with a fake JWT under the keys the app's auth store reads
     (confirm against `src/api/auth.ts` / the Zustand auth store — likely
     `access`/`refresh` + a cached `user`), so `ProtectedRoute` admits the student;
  2. registers `page.route('**/api/v1/**', …)` fulfils that return minimal valid
     JSON for the core-loop reads (current user, assignments list, one assignment
     detail with a couple of subparts, proficiency summary, an SRS due item). Keep
     fixtures tiny — axe only needs the DOM to render, not real data.
- Extend the `ROUTES` table in `e2e/a11y.spec.ts` with an optional `auth?: boolean`
  and the student routes (use concrete params for the `:id`/`:entryId` routes that
  match the mocked fixtures):
  - `{ name: 'student-dashboard', path: '/student', auth: true, gate: false }`
  - `{ name: 'assignment-detail', path: '/student/assignments/1', auth: true, gate: false }`
  - `{ name: 'proficiency', path: '/student/proficiency', auth: true, gate: false }`
  - `{ name: 'srs-drill', path: '/student/srs-drill/1', auth: true, gate: false }`
  - When `auth`, the test applies the auth helper + route mocks before `page.goto`.
- All **reporting-mode** in this PR. Emit `axe-report/<route>.json` as before.

**Verify.** `npx playwright test a11y` — all routes (public + new student) pass in
reporting mode; inspect the new `axe-report/student-*.json` to build the A11Y-7 fix
list. CI `frontend-e2e` stays green (non-gating).

**What could go wrong.** The auth-store key names and the exact API read endpoints
must match the real app or the route renders a redirect/spinner instead of content
— confirm by reading `src/api/auth.ts`, the auth Zustand store, and each page's
React Query keys before mocking. If a page makes a write/poll axe can't settle on,
wait for the page's stable `h1`/main region (as the existing spec does) rather than
`networkidle` alone. Keep the fixture JSON minimal and colocated.

### A11Y-7 — Remediate student core-loop findings *(Improve, depends A11Y-6)*

**Frontend.** Fix the structural/contrast violations the A11Y-6 inventory surfaces
on `features/student/{StudentDashboard,AssignmentDetailPage,ProficiencyPage,SRSDrillPage}.tsx`
(+ the shared widgets they render):

- **Labels:** every answer input (MCQ radios, numeric/fill-blank fields,
  auto-save textareas) gets a programmatic label — `<label htmlFor>` /
  `aria-label` / `aria-labelledby` (a fieldset `<legend>` per subpart is ideal for
  radio groups). Reuse LA i18n keys; any new visible label lands in **en/hi/mr** in
  the same PR (key-parity guard enforces).
- **Landmarks:** confirm each page renders inside the single `#main-content`/`<main>`
  from `AppShell`; no duplicate/unlabelled landmarks.
- **Headings:** one `h1` per page, no skipped levels (dashboard section headings,
  proficiency chapter rows, drill question heading).
- **Contrast:** should already be handled by A11Y-4's token sweep; fix any
  remaining page-local `text-brand-600`/`text-ink-400` small-text instances the
  inventory flags.
- Keep the SVG sparklines (`ProficiencyPage`) accessible: `role="img"` +
  `aria-label` summarizing the trend (they're decorative-data, not interactive).

**Verify.** Re-run `npx playwright test a11y` and confirm the targeted violation
families drop to zero on the student routes (still `gate: false` here); existing
student-page Vitest suites pass; `lint`/`tsc`/`build` green; new keys in all three
locales.

**What could go wrong.** Adding `<fieldset>`/`<legend>` can shift the V2 form
layout — use `sr-only` legends where a visible group label is redundant with an
adjacent heading. Don't regress the auto-save debounce or submit flow while
relabelling inputs.

## F. Legacy analysis & improvement opportunities

- **Legacy had no accessibility story at all** — Django 1.11 templates, no ARIA, no
  contrast discipline, no keyboard story, no automated checking. Nothing to *port*;
  this is **net-new platform capability** built on the modern app.
- **What to preserve:** the M6-01 skip-link + `#main-content` landmark, the V2
  "Accessible by default" principle, the Batch-1 per-route axe harness + jsx-a11y
  gate, and the `#FF6F00` brand identity (kept as the decorative anchor).
- **What to improve:** (1) turn the deferred brand-contrast finding into a
  *documented, enforced* token-usage rule so the CTA is legible for low-vision
  users without losing the brand; (2) extend the measured-and-gated contract from
  the front door to the student core loop — the part of the product students
  actually use; (3) add a real keyboard-focus story, which axe can't measure and
  legacy never had. This is the standard modern ed-tech AA bar.
