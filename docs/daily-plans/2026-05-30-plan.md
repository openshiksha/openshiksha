## A. Today's objective

Make student-facing question content actually render: HTML + LaTeX (`\(…\)`,
`$…$`, `$$…$$`, plus block macros like `\over` / `\sqrt`) in question text,
MCQ options, and worked solutions — across `QuestionCard`, the SRS drill, and
the teacher Question Bank preview — so a parent or 12-year-old sees a real
question, not raw markup.

## B. Why this matters

- **Unblocks the V2 initiative.** M7 was discovered while validating the V2
  shell+home+login as `student_demo`. The brand now looks credible, but the
  primary surface — the question — is broken. Every other M4 product surface
  loses meaning until questions render correctly.
- **Compounds with prior work.** The Cabinet import (P8, shipped 2026-05-27)
  brought in 679 real questions whose content is HTML containing inline LaTeX
  in the legacy `\(…\)` and `\over`/`\sqrt`/`\frac` style. Until we render
  those, the import effectively isn't visible.
- **Improves on legacy.** Legacy relied on a server-rendered Django template
  passing raw HTML to MathJax. We can do better: sanitised HTML +
  `katex.renderToString` (already a dependency) — faster, no MathJax, no XSS
  if we use a proper sanitiser, and works inside the V2 token system.

## D. Concrete implementation plan

### Priority 1 — `RichContent` renderer

**Create** `frontend_modern/src/shared/ui/RichContent.tsx`:

```ts
import DOMPurify from 'dompurify';
import katex from 'katex';
import 'katex/dist/katex.min.css';

// 1. Sanitise the incoming HTML (allow basic inline tags + img).
// 2. Walk the sanitised DOM; for every text node, replace LaTeX spans
//    ($...$, $$...$$, \(...\), \[...\]) with KaTeX-rendered HTML.
// 3. Return as { __html } via dangerouslySetInnerHTML on a wrapper.
//
// Token-only styling: wrapper is `prose-osh` (Tailwind plugin OR a small
// CSS class in index.css) — warm `ink-600` body, `ink-900` headings, brand
// links. NO indigo/blue/cold-gray.
```

- Add `dompurify` (+ `@types/dompurify`) to `frontend_modern/package.json`.
- Allowlist tags: `p, br, span, strong, em, b, i, u, sup, sub, ul, ol, li,
  code, pre, img, table, thead, tbody, tr, td, th`. Drop `script`, `iframe`,
  `style`, all event-handler attributes. `img` keeps `src/alt/width/height`
  only — and `src` restricted to http(s) and the configured CDN host.
- LaTeX delimiter set (in this priority order):
  - `$$…$$` and `\[…\]` → block (`displayMode: true`).
  - `$…$` and `\(…\)` → inline.
- Edge cases: balanced delimiters across HTML element boundaries are rare in
  the Cabinet corpus; if KaTeX errors, fall back to the literal source with a
  small `text-rose-700` underline so authors notice.

### What could go wrong

- **Sanitiser too strict** — some Cabinet questions use `<table>` for
  alignment. Allowlist tables explicitly.
- **KaTeX missing macros** — `\over`, `\sqrt 3\over 2` are valid KaTeX but
  fragile. Test on a real Cabinet question (subject = Math) before declaring
  done.
- **`dangerouslySetInnerHTML` + DOM walk** — after sanitising, render once;
  don't re-render on every keystroke. Memoise `RichContent` on `text` prop.
- **Vite hot-reload on Windows Docker** doesn't always pick up new files
  under `shared/ui/`: `docker compose restart frontend` if needed.

## F. Legacy analysis & improvement opportunities

| Feature | Legacy did | What was good | What was limited | How to improve |
|---|---|---|---|---|
| Question rendering | Django template → MathJax in the browser; HTML came from Cabinet | Worked with arbitrary HTML | MathJax is heavy (~300KB), slow to first render, hard to theme | KaTeX (already in deps) is synchronous, ~10× smaller, themable via CSS. Sanitise via DOMPurify so we can drop trust in Cabinet's HTML and still keep `<img>` for figure questions. |
| MCQ options | Same template/MathJax pipeline | Math in options worked | Coupled to the assignment-detail page only | A shared `RichContent` primitive means options, hints, solutions, AI explanations, and parent-summary emails (eventually) all render identically. |
| Worked solutions | Server-rendered, always-visible | Simple | Spoiled the answer | Already gated behind `CollapsibleReveal`; today we just make the *content* render right. |
