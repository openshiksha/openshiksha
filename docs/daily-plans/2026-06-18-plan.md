## A. Today's objective

Ship the **route-level mobile layouts** later-phase as a batch of 5 atomic PRs.
Today's outcome: the **dense teacher surfaces that still overflow horizontally on a
phone** (the `<table>`-based Class Health and Assignment-detail submissions views,
plus the multi-column Create-Question and Open-Response-Grading forms) become
**readable and usable on a 360 px screen** — no horizontal scroll, no clipped
columns — via a small shared `ResponsiveTable` primitive and per-surface stacking.
This is the **last named later-phase**; landing it completes the Mobile Shell &
PWA-Offline initiative end-to-end.

## B. Why this matters

- **Closes the initiative.** The [Mobile Shell doc](../initiatives/2026-mobile-shell-pwa-offline.md)
  lists exactly two later phases. Web push shipped 2026-06-17 (MPN-1..5, #375–#379).
  **Route-level mobile layouts is the only thing left.** Batches 1–3 made the PWA
  installable, offline-write-tolerant, and push-capable — but a teacher who installs
  it to a phone still hits a horizontally-scrolling submissions table. This batch
  finishes the "feels native on a phone" promise the North Star implies.
- **Mission-core for the target market.** Teachers in Indian K-12 schools are
  frequently on budget Android phones. The student core loop is already mobile-first
  (V2 + M5-01 bottom tabs); the **teacher** surfaces are the remaining gap — they
  were built table-first for desktop and only band-aided with `overflow-x-auto`,
  which on a phone means pinch-zoom-and-scroll, the exact UX the initiative set out
  to kill.
- **Lowest-risk, purely-frontend close-out.** No backend, no new dependency, no
  schema. Each surface is an independent, well-bounded layout change behind the
  existing `sm:` breakpoint, defended by the same `npm run build` entry-chunk guard.
  The shared primitive (RML-1) makes the rest mechanical and consistent.
- **Improves on legacy.** Legacy OpenShiksha (Django 1.11 server-rendered tables)
  had **no** mobile teacher experience at all. Responsive card layouts are net-new.

## D. Concrete implementation plan

### RML-1 — `ResponsiveTable` primitive + ClassHealthPanel *(New, build first)*

**Frontend.**
- New `frontend_modern/src/shared/ui/ResponsiveTable.tsx`. Generic, typed:
  ```tsx
  export interface ResponsiveColumn<T> {
    key: string;
    header: ReactNode;
    /** cell renderer for the desktop table + the card value */
    cell: (row: T) => ReactNode;
    align?: 'left' | 'right';
    /** if true, used as the card's title row (rendered prominently, no label) */
    primary?: boolean;
  }
  interface Props<T> {
    columns: ResponsiveColumn<T>[];
    rows: T[];
    rowKey: (row: T) => string | number;
    caption?: ReactNode;        // sr-only table caption
    'aria-label'?: string;
  }
  ```
  - **≥ `sm`**: render a real semantic `<table>` (`hidden sm:table` — match the
    existing `BottomNav`/`Navbar` breakpoint convention in the repo, not a JS media
    query) styled like the current panels (`thead` ink-50, row borders, hover).
  - **< `sm`**: render `<ul className="sm:hidden …">`; each row is an `os-card`-ish
    block: the `primary` column as the card heading, every other column as a
    `<div className="flex justify-between"><dt>{header}</dt><dd>{cell}</dd></div>`
    label/value pair (use a `<dl>` for semantics). No horizontal scroll.
  - Keep it **dependency-free** and tiny; colours/spacing via the existing Tailwind
    tokens (`ink-*`, `brand-*`). Export from `shared/ui/index.ts`.
- **First consumer — `ClassHealthPanel.tsx`** (`features/teacher/ClassHealthPanel.tsx:80-121`):
  replace the `-mx-1 overflow-x-auto` + `min-w-[22rem]` `<table>` with
  `<ResponsiveTable>` (columns: Chapter [primary], Avg, Struggling, Status). The
  status dot + label and the `n/m struggling` cell move into `cell` renderers. All
  the existing `t('teacher.th*')` keys are reused as `header`s — no new i18n.
- **Test (Vitest):** `ResponsiveTable.test.tsx` — renders all rows; both the table
  and the card list are in the DOM (one hidden per breakpoint via class, JSDOM can't
  evaluate the media query, so assert both structures + the `sm:hidden`/`hidden
  sm:table` classes); `rowKey` used; empty `rows` renders nothing/caption only.
  Update `ClassHealthPanel`'s existing render if asserted.
- **Verify:** `npm run test`, `npm run lint`, `npx tsc --noEmit`, and `npm run build`
  — confirm entry chunk unchanged vs the 160 kB CI guard (the primitive is small and
  imported into already-lazy teacher routes).
- **What could go wrong:** keep the desktop table visually identical to today's so
  this reads as a refactor, not a redesign. Don't introduce a runtime `matchMedia`
  hook — the dual-render + Tailwind `sm:` approach is what the repo already uses
  (`DueForReviewPanel`, `Navbar`) and avoids hydration/SSR-style flicker.

## F. Legacy analysis & improvement opportunities

- **Teacher tables:** Legacy OpenShiksha (Django 1.11, server-rendered) presented
  classroom/assignment data as desktop HTML tables with **no responsive behaviour** —
  on a phone you pinch-zoomed. The modern app improved on this for the *student* loop
  (mobile-first since V2 + M5-01) but the *teacher* surfaces were ported table-first
  and only patched with `overflow-x-auto`, which preserves the legacy
  scroll-and-squint UX. **What to preserve:** the information density and column
  semantics (teachers do want to scan many students/chapters) — so we keep a real
  table on tablet/desktop. **What to improve:** below `sm`, swap the scroll for a
  stacked label/value card so every datum is legible without zoom. This is the
  responsive pattern modern ed-tech dashboards use and the legacy system never had.
- **Localization gap (found en route):** `TeacherAssignmentDetailPage` still has
  hardcoded English — a regression against the LA initiative's parity contract.
  RML-2 folds it back into the i18n registry while the file is open.
