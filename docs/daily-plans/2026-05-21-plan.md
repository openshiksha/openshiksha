## B. Why This Matters

- **SRS Drill Mode**: The spaced repetition infrastructure is fully built — SM-2 model (`SpacedRepetitionEntry`), `due/` API action, `DueForReviewPanel` UI. But tapping a due item does nothing. A learning platform that tells students what to review but doesn't let them review it is friction-generating, not habit-forming. The drill mode is the payoff that makes the SM-2 scheduler mean something.

- **Activity Streaks**: Streaks are the single most proven gamification mechanic in ed-tech (Duolingo's core retention driver). A student who sees "🔥 7-day streak" at the top of their dashboard has a concrete reason to open the platform today. The data we need already exists — `Submission.submitted_at` — so the model is lightweight and the signal is immediate.

- **Question Content Search**: Teachers use the question bank page to find questions for assignments. Currently `QuestionViewSet.search_fields` only covers `chapter__name` and `subject__name` — searching by question text itself returns nothing. Adding `subparts__question_text` and `tags__name` is a one-liner that makes the question bank dramatically more useful.

#### Step 1 — Backend: `review` action on `SpacedRepetitionViewSet`

**File**: `backend/openshiksha/apps/ai/views.py`

Add to `SpacedRepetitionViewSet`:

```python
@action(detail=True, methods=["get"], url_path="review")
def review(self, request, pk=None):
    """
    GET /api/v1/ai/spaced-repetition/{id}/review/
    Returns up to 5 questions from the chapter associated with this SRS entry.
    Only the owning student may access this.
    """
    entry = self.get_object()
    if entry.student_id != request.user.id:
        return Response({"detail": "Not found."}, status=status.HTTP_404_NOT_FOUND)

    from openshiksha.apps.core.models import Question

    questions = (
        Question.objects.filter(chapter=entry.knowledge_node.chapter)
        .prefetch_related("subparts__tags", "tags")
        .order_by("?")[:5]  # random sample; reproducible shuffle not needed for review
    )

    # Reuse existing QuestionSerializer
    from openshiksha.apps.api.serializers.core import QuestionSerializer

    return Response(
        {
            "entry_id": entry.id,
            "chapter_name": entry.knowledge_node.chapter.name,
            "subject_name": entry.knowledge_node.subject.name,
            "questions": QuestionSerializer(questions, many=True, context={"request": request}).data,
        }
    )
```

Design rationale:
- Up to 5 questions keeps a review session short (5–10 minutes), matching SRS best practices.
- `order_by("?")` gives variety across review sessions. No croupier randomization for review — students should see real questions, not shuffled variants (review is about recall, not cheating prevention).
- Returns the full `QuestionSerializer` payload so the frontend can reuse `QuestionCard` components exactly.

#### Step 2 — Backend: `mark_reviewed` action on `SpacedRepetitionViewSet`

```python
@action(detail=True, methods=["post"], url_path="mark-reviewed")
def mark_reviewed(self, request, pk=None):
    """
    POST /api/v1/ai/spaced-repetition/{id}/mark-reviewed/
    Body: {"score": 0.8}  — fraction 0.0–1.0 (fraction of questions answered correctly)

    Updates SM-2 schedule:
    - score >= 0.6 → successful recall, interval grows
    - score < 0.6 → failed recall, reset to interval=1
    """
    entry = self.get_object()
    if entry.student_id != request.user.id:
        return Response({"detail": "Not found."}, status=status.HTTP_404_NOT_FOUND)

    score = request.data.get("score")
    try:
        score = float(score)
        if not (0.0 <= score <= 1.0):
            raise ValueError()
    except (TypeError, ValueError):
        return Response({"detail": "score must be a float between 0.0 and 1.0."}, status=400)

    from datetime import timedelta
    from django.utils import timezone

    # SM-2 update (simplified from models.py docstring)
    if score >= 0.60:
        if entry.repetitions == 0:
            new_interval = 1
        elif entry.repetitions == 1:
            new_interval = 6
        else:
            new_interval = round(entry.interval_days * entry.easiness_factor)
        new_ef = max(1.3, entry.easiness_factor + 0.1 - (1 - score) * 0.8)
        new_reps = entry.repetitions + 1
    else:
        new_interval = 1
        new_ef = entry.easiness_factor  # unchanged on failure
        new_reps = 0

    entry.interval_days = new_interval
    entry.easiness_factor = new_ef
    entry.repetitions = new_reps
    entry.next_review_date = timezone.localdate() + timedelta(days=new_interval)
    entry.last_reviewed_at = timezone.now()
    entry.save(update_fields=[
        "interval_days", "easiness_factor", "repetitions",
        "next_review_date", "last_reviewed_at", "updated_at"
    ])

    return Response(self.get_serializer(entry).data)
```

Design rationale:
- The SM-2 algorithm is already documented in the model docstring. This is the first time it's actually applied — the model had the algorithm description but no method to execute it.
- `update_fields` avoids a full row write on a concurrent multi-student system.
- 0.6 threshold matches the original SM-2 specification ("successful recall" boundary).

#### Step 4 — Frontend: `useSRSDrill.ts` hook

**New file**: `frontend_modern/src/features/student/useSRSDrill.ts`

```typescript
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { apiClient } from '@/api/client';

export interface SRSDrillData {
  entry_id: number;
  chapter_name: string;
  subject_name: string;
  questions: Question[];  // reuse existing Question type
}

export const useSRSDrill = (entryId: number | null) =>
  useQuery<SRSDrillData>({
    queryKey: ['srs', 'drill', entryId],
    queryFn: async () => {
      const { data } = await apiClient.get(`/ai/spaced-repetition/${entryId}/review/`);
      return data;
    },
    enabled: !!entryId,
    staleTime: 0,  // always fresh — random sample each load
  });

export const useMarkReviewed = () => {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async ({ entryId, score }: { entryId: number; score: number }) => {
      const { data } = await apiClient.post(
        `/ai/spaced-repetition/${entryId}/mark-reviewed/`,
        { score }
      );
      return data;
    },
    onSuccess: () => {
      // Invalidate due list so updated entry disappears or shows new date
      queryClient.invalidateQueries({ queryKey: ['srs', 'due'] });
      queryClient.invalidateQueries({ queryKey: ['srs', 'drill'] });
    },
  });
};
```

#### Step 5 — Frontend: `SRSDrillPage.tsx`

**New file**: `frontend_modern/src/features/student/SRSDrillPage.tsx`

```tsx
import { useState } from 'react';
import { useParams, useNavigate } from 'react-router-dom';
import { useSRSDrill, useMarkReviewed } from './useSRSDrill';
import { QuestionCard } from './QuestionCard';  // already exists, renders LaTeX MCQ/numeric

/**
 * SRS drill flow:
 * 1. Load chapter's questions via /review/
 * 2. Student answers each question (same QuestionCard as AssignmentDetailPage)
 * 3. Score is calculated locally (correct answers / total)
 * 4. POST score to /mark-reviewed/ → SM-2 updates
 * 5. Show result screen (score + new review date)
 */
export const SRSDrillPage = () => {
  const { entryId } = useParams<{ entryId: string }>();
  const navigate = useNavigate();
  const parsedId = entryId ? parseInt(entryId, 10) : null;
  const { data: drill, isLoading } = useSRSDrill(parsedId);
  const { mutate: markReviewed, isPending } = useMarkReviewed();

  // Local answer state: subpart_id → student answer
  const [answers, setAnswers] = useState<Record<number, string | number>>({});
  const [submitted, setSubmitted] = useState(false);
  const [result, setResult] = useState<{ score: number; nextDate: string } | null>(null);

  const handleAnswer = (subpartId: number, value: string | number) => {
    setAnswers((prev) => ({ ...prev, [subpartId]: value }));
  };

  const handleSubmit = () => {
    if (!drill) return;

    // Calculate score: fraction of subparts answered correctly
    let correct = 0;
    let total = 0;

    for (const q of drill.questions) {
      for (const subpart of q.subparts) {
        total++;
        const studentAnswer = answers[subpart.id];
        if (studentAnswer !== undefined) {
          // For MCQ: compare to correct_answer index; for numeric/text: string compare
          const isCorrect = String(studentAnswer) === String(subpart.correct_answer);
          if (isCorrect) correct++;
        }
      }
    }

    const score = total > 0 ? correct / total : 0;
    setSubmitted(true);

    markReviewed(
      { entryId: drill.entry_id, score },
      {
        onSuccess: (entry) => {
          setResult({
            score,
            nextDate: entry.next_review_date,
          });
        },
      }
    );
  };

  if (isLoading) {
    return (
      <div className="max-w-2xl mx-auto px-4 py-8 text-center text-gray-400">
        Loading review session…
      </div>
    );
  }

  if (!drill) {
    return (
      <div className="max-w-2xl mx-auto px-4 py-8 text-center text-gray-400">
        Review session not found.
      </div>
    );
  }

  if (result) {
    const pct = Math.round(result.score * 100);
    const passed = result.score >= 0.6;
    return (
      <div className="max-w-2xl mx-auto px-4 py-8">
        <div className={`rounded-2xl p-8 text-center ${passed ? 'bg-green-50' : 'bg-red-50'}`}>
          <div className="text-5xl mb-4">{passed ? '🎉' : '📚'}</div>
          <h2 className="text-2xl font-bold text-gray-900 mb-2">
            {passed ? 'Great review!' : 'Keep practicing!'}
          </h2>
          <p className="text-gray-600 mb-1">
            You scored <span className="font-semibold">{pct}%</span> on {drill.chapter_name}
          </p>
          <p className="text-sm text-gray-500 mb-6">
            {passed
              ? `Next review scheduled for ${result.nextDate}`
              : `Review again tomorrow — interval reset to 1 day`}
          </p>
          <button
            onClick={() => navigate('/student')}
            className="bg-indigo-600 text-white px-6 py-2.5 rounded-lg font-medium hover:bg-indigo-700 transition-colors"
          >
            Back to Dashboard
          </button>
        </div>
      </div>
    );
  }

  return (
    <div className="max-w-2xl mx-auto px-4 py-6 sm:py-8">
      {/* Header */}
      <div className="mb-6">
        <button
          onClick={() => navigate('/student')}
          className="text-sm text-indigo-600 hover:text-indigo-800 mb-3 flex items-center gap-1"
        >
          ← Back
        </button>
        <div className="flex items-center gap-2">
          <span className="text-2xl">🔁</span>
          <div>
            <h1 className="text-xl font-bold text-gray-900">{drill.chapter_name}</h1>
            <p className="text-sm text-gray-500">{drill.subject_name} · Spaced review</p>
          </div>
        </div>
      </div>

      {/* Questions */}
      {drill.questions.length === 0 ? (
        <div className="text-center py-12 text-gray-400">
          <p>No questions available for this chapter yet.</p>
          <p className="text-sm mt-1">Ask your teacher to add questions to this chapter.</p>
          <button
            onClick={() => navigate('/student')}
            className="mt-4 text-sm text-indigo-600 hover:underline"
          >
            Back to Dashboard
          </button>
        </div>
      ) : (
        <>
          <div className="space-y-4">
            {drill.questions.map((question) => (
              <QuestionCard
                key={question.id}
                question={question}
                answers={answers}
                onAnswer={handleAnswer}
                readOnly={submitted}
              />
            ))}
          </div>

          {!submitted && (
            <div className="mt-6">
              <button
                onClick={handleSubmit}
                disabled={isPending}
                className="w-full sm:w-auto bg-indigo-600 text-white px-8 py-3 rounded-xl font-semibold hover:bg-indigo-700 disabled:opacity-50 transition-colors"
              >
                {isPending ? 'Saving…' : 'Submit Review'}
              </button>
            </div>
          )}
        </>
      )}
    </div>
  );
};
```

#### What Could Go Wrong

- **`order_by("?")` is slow on large question tables**: PostgreSQL's `ORDER BY RANDOM()` is a full table scan. Fine for now (question bank is small). When question bank grows large, replace with `Question.objects.filter(...).values_list('id', flat=True)` → random sample IDs → `Question.objects.filter(id__in=ids)`.
- **`QuestionCard` prop interface**: Check that `QuestionCard` accepts the same `answers`, `onAnswer`, `readOnly` props. If the existing component doesn't accept `readOnly`, add a `disabled` prop that disables inputs after submit.
- **SRS entry with no questions**: If the chapter has no questions yet, the review endpoint returns `questions: []`. The frontend handles this gracefully with an empty-state message.
- **Student navigates away mid-drill**: No autosave — answers are in local state. If the student navigates away, answers are lost and they can retry the drill (a fresh random sample is returned next time). This is acceptable for a review session.

```python
class StudentStreak(models.Model):
    """
    Tracks daily activity streaks for students.

    Incremented whenever a student submits an assignment (submitted_at set).
    A streak is broken if there is no submission on any calendar day since last_activity_date.

    Design: one row per student — updated in-place, not append-only.
    Simple and readable. If we need streak history later, we can add a
    StreakEvent append-only log. For now, current + longest is enough.
    """

    student = models.OneToOneField(
        "User",
        on_delete=models.CASCADE,
        related_name="streak",
        limit_choices_to={"role__in": ["student", "open_student"]},
    )
    current_streak = models.PositiveIntegerField(default=0, help_text="Consecutive days with activity")
    longest_streak = models.PositiveIntegerField(default=0, help_text="All-time longest streak")
    last_activity_date = models.DateField(
        null=True, blank=True, help_text="Date of the most recent activity"
    )
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = "student_streaks"

    def __str__(self):
        return f"Streak({self.student_id}): {self.current_streak} days"

    def record_activity(self, activity_date):
        """
        Called with today's date when a student submits an assignment.

        Rules:
        - Same day as last activity → no-op (streak already counted)
        - Consecutive day → current_streak += 1
        - Gap of 1+ days → current_streak = 1 (reset, new streak starts today)
        """
        from datetime import timedelta

        if self.last_activity_date is None:
            # First ever activity
            self.current_streak = 1
        elif activity_date == self.last_activity_date:
            return  # already counted today, do nothing
        elif activity_date == self.last_activity_date + timedelta(days=1):
            # Consecutive day
            self.current_streak += 1
        else:
            # Gap — streak broken
            self.current_streak = 1

        self.last_activity_date = activity_date
        if self.current_streak > self.longest_streak:
            self.longest_streak = self.current_streak
        self.save(update_fields=["current_streak", "longest_streak", "last_activity_date", "updated_at"])
```

from django.db.models.signals import post_save
from django.dispatch import receiver

@receiver(post_save, sender=Submission)
def update_student_streak(sender, instance, **kwargs):
    """
    When a Submission is saved with submitted_at set, record activity on the
    student's streak for that date.
    """
    if not instance.submitted_at:
        return  # draft save — not a submission yet

    activity_date = instance.submitted_at.date()
    streak, _created = StudentStreak.objects.get_or_create(student_id=instance.student_id)
    streak.record_activity(activity_date)

@action(detail=False, methods=["get"], url_path="me/streak")
def me_streak(self, request):
    """
    GET /api/v1/users/me/streak/
    Returns the current student's streak data.
    """
    user = request.user
    if user.role not in (UserRole.STUDENT, UserRole.OPEN_STUDENT):

#### What Could Go Wrong

- **Signal not registered**: If `post_save` signal isn't connected at startup, streaks never update. Ensure `CoreConfig.ready()` imports the signals module. Test by creating a `Submission` in tests and checking `StudentStreak.objects.filter(student=...)`.
- **Timezone confusion on activity_date**: `submitted_at` is UTC. `instance.submitted_at.date()` in the signal gives UTC date. A student who submits at 11 PM IST (5:30 PM UTC) gets credit for the UTC date, not IST. Acceptable for Phase 1. Future: use `django.utils.timezone.localdate()` in the signal to respect the school's timezone setting.
- **`get_or_create` race condition**: If two submissions arrive for the same student simultaneously (unlikely — `unique_together` on `[assignment, student]` prevents duplicate submissions), two `get_or_create` calls could both try to create. Use `select_for_update()` or `update_or_create()` if race conditions become a concern.
- **Streak badge on every render**: `useStreak` fetches on mount. `staleTime: 60_000` means it refetches at most once per minute. This is fine for a daily metric.

## F. Legacy Analysis & Improvement Opportunities

### SRS (Priority 1)

**Legacy**: No spaced repetition existed. Legacy had no concept of scheduling review — students practiced whatever was assigned by the teacher. The platform was entirely teacher-driven; students had no self-directed practice mechanism.

**Modern improvement**: SM-2 spaced repetition is the gold standard for long-term retention (used by Anki, Duolingo, Memrise). The scheduler was built in May 2026. The drill mode is the first time a student can practice independently of teacher assignments. This is a meaningful shift: the platform moves from passive "wait for teacher to assign" to active "here's what you need to review based on your own performance history."

Future: Integrate drill scores back into `StudentMastery` and `StudentProficiency` (currently drill scores aren't fedback to the proficiency engine — they update the SRS schedule only). Phase 2 would write `Tick` records from drill attempts to feed the full analytics pipeline.

### Streaks (Priority 2)

**Legacy**: No engagement mechanics. The platform had no way to motivate daily use beyond teacher-assigned homework.

**Modern improvement**: Streaks create habit loops. Research shows even a 3-day streak significantly increases return probability (loss aversion + identity: "I'm a daily learner"). The implementation is deliberately simple — Phase 1 is just current/longest streak with a fire emoji. Future phases: streak freeze (grace day if student misses), streak milestones (7-day badge, 30-day badge), streak leaderboard in classroom.

### Question Search (Priority 3)

**Legacy**: Teachers browsed Cabinet by chapter — there was no free-text search. Finding a "photosynthesis" question required knowing it was in Chapter 3 of Biology.

**Modern improvement**: Full-text search across `question_text` and `tags` makes the question bank actually navigable. As the bank grows (from seed data to imported legacy questions to teacher-authored content), search becomes essential. DRF's `SearchFilter` is already wired — this is a configuration change that unlocks the feature.
