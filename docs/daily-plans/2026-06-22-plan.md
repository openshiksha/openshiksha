## D. Concrete implementation plan

### OSS-6 — `.github/` issue + PR templates *(New, independent, build first)*

**Current state.** `.github/` has `dependabot.yml` + `workflows/` only — **no
`ISSUE_TEMPLATE/` and no PR template.**

**Create:**
- `.github/ISSUE_TEMPLATE/bug_report.md` — front-matter (`name`, `about`,
  `title: "[Bug]: "`, `labels: bug`); sections: *What happened / Expected /
  Steps to reproduce / Environment (browser, role: student-teacher-parent-admin) /
  Screenshots / Severity*.
- `.github/ISSUE_TEMPLATE/feature_request.md` — (`title: "[Feature]: "`,
  `labels: enhancement`); sections: *Problem / Proposed solution / Who benefits
  (which role) / Alternatives considered*.
- `.github/ISSUE_TEMPLATE/config.yml` — `blank_issues_enabled: false`; a
  `contact_links` entry pointing security reports to `SECURITY.md` (do **not** file
  vulns as public issues) and general questions to GitHub Discussions if enabled
  (else omit).
- `.github/pull_request_template.md` — *Summary / Type (port/improve/new/fix/docs) /
  Initiative + increment ID / How tested / Checklist* (CI green, docs/ledger
  updated, no secrets, follows commit conventions in `CONTRIBUTING.md`). Mirror the
  repo's real commit style (`feat(scope): …`).

**Legacy reference.** None — the archived monolith had no community scaffolding.
Net-new. Keep the tone consistent with the existing `CONTRIBUTING.md`.

**Verify.** Files render in GitHub's "New issue" chooser (can't test locally —
confirm YAML front-matter is valid: `python -c "import yaml,sys; yaml.safe_load(open(f).read().split('---')[1])"` for each). `pre-commit` (trailing-whitespace,
end-of-file) passes. No CI impact.

**What could go wrong.** A malformed `config.yml` silently disables the template
chooser — keep it minimal and valid. Don't reference a Discussions URL that isn't
enabled (dead link); omit that contact link if unsure.

### OSS-8 — Renderable architecture diagram *(Improve, build third — touches README)*

**Current state.** README `## Architecture` (lines ~29–41) is **ASCII art** in a
fenced code block. It reads but doesn't render as a graphic on GitHub and is hard to
extend.

**Do:**
- Replace the ASCII block with a **Mermaid `flowchart`** (GitHub renders ` ```mermaid `
  natively). Model the real request flow already documented:
  `Browser --HTTPS--> Traefik (k3s ingress)`; Traefik routes `/api/* /admin/*
  /static/*` → **Django + Daphne backend**, everything else → **React SPA (nginx)**;
  backend → **PostgreSQL** (data) and **Redis** (cache/broker); **Celery worker +
  beat** ← Redis (async grading, AI tasks); backend → **AI providers** (Gemini /
  Claude, Ollama fallback) per the stack table.
- **Keep** the existing stack table (lines ~43–51) — the diagram shows topology, the
  table shows tech. Optionally keep the ASCII as a fallback `<details>` for non-Mermaid
  renderers (optional; Mermaid is fine on GitHub).

**Rationale (Improve).** A rendered diagram communicates the architecture at a
glance and is the explicit OSS-8 backlog item ("request flow: Traefik → backend
/api,/admin,/static + frontend; Postgres/Redis/Celery").

**Verify.** Paste the Mermaid into the GitHub preview (or mermaid.live) to confirm
it parses and renders; arrows/labels match the prose in `## CI/CD pipeline` and
`docs/deploy/README.md`. `pre-commit` passes. No CI impact.

**What could go wrong.** Mermaid syntax errors render as a raw code block — validate
before pushing. Don't over-detail (no per-pod boxes); match the abstraction level of
the prose. Keep node labels short so it renders on mobile GitHub.

### OSS-7 — Consolidate root dev docs under `docs/` *(Improve, build fourth — touches README links)*

**Current state.** Four loose dev guides sit at the repo root next to the public
files: `CHEAT_SHEET.md`, `GIT_STRATEGY.md`, `LOCAL_DEVELOPMENT.md`,
`SETUP_MODERNIZATION.md`. The README + CONTRIBUTING link to them at the root path.

**Do:**
- `git mv` the four into **`docs/dev/`** (preserve history). Keep the public-facing
  trio at root (`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`,
  `LICENSE.md`) — those are GitHub-special and belong at root.
- Create **`docs/dev/README.md`** — a short index: one line per guide
  (cheat-sheet / git-strategy / local-development / setup-modernization) with a
  sentence each.
- **Fix every inbound link.** Grep the repo for references to the four filenames and
  repoint them: README `## Quickstart` (`LOCAL_DEVELOPMENT.md` → `docs/dev/local-development.md`),
  README `## Documentation` block (Local development, Git strategy links),
  `CONTRIBUTING.md`, and any cross-links between the guides themselves.
  `grep -rn "LOCAL_DEVELOPMENT\|GIT_STRATEGY\|CHEAT_SHEET\|SETUP_MODERNIZATION" --include="*.md" .`
- Consider renaming to kebab-case on the move (`local-development.md`) for docs/
  consistency — update links accordingly. (Optional but tidier; if done, do it in
  the same `git mv` so history follows.)
- Add the `docs/dev/` index to the README `## Documentation` list.

**Rationale (Improve).** The DoD says "dev docs consolidated/indexed under `docs/`
(no stray, stale root guides)." This is the last structural cleanup; the root then
shows only the modern stack + GitHub-special files.

**Verify.** `grep` finds **zero** remaining links to the old root paths; every moved
doc opens from its new path; `git log --follow docs/dev/local-development.md` shows
preserved history. `pre-commit` passes. No CI impact (no code references these).

**What could go wrong.** A missed inbound link 404s for newcomers — the grep must be
exhaustive (also check `docs/**` and the initiative docs). Don't move the four
GitHub-special root files. If `LOCAL_DEVELOPMENT.md` is referenced from a CI workflow
comment or `.env.example`, repoint that too.

  `gh repo edit openshiksha/openshiksha --description "Modern K-12 practice-learning platform for India — Django + React, AI-assisted." --homepage "https://openshiksha.org"`

  `gh repo edit openshiksha/openshiksha --add-topic education,edtech,k12,django,react,typescript,india,learning-platform`.

  ship as the PR**.)

  detector prefers `LICENSE` w/o extension for auto-detection — if the current
  `LICENSE.md` isn't auto-detected in the repo sidebar, consider adding a plain
  `LICENSE` copy or note the SPDX id at the top). Confirm the README `## License`
  section names it and links it.
- Add a **license badge** (+ optionally a CI-status badge for `ci-cd.yaml`) to the
  top of the README.

**Rationale.** Metadata + a detected license are what make the repo
discoverable and legally legible — the final public-readiness polish (OSS-10).

**Verify.** `gh repo view openshiksha/openshiksha` shows the new description/topics/
homepage (or the output notes the scope gap); the GitHub repo sidebar shows the
detected license; README badges render. No CI impact.

**What could go wrong.** `gh repo edit` may lack admin scope in the routine's token —
**don't fail the batch on it**; ship the README/badge/license-file part and surface
the metadata command for a human to run. Don't change the license **terms** — this is
verification + surfacing only.
