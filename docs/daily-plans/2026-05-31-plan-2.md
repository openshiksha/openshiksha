## B. Why this matters

The Cabinet bank is the platform's *entire* real K–12 content — 644 questions /
1734 subparts. The M7-01 `RichContent` primitive and M7-02 substitution fix
landed, so content now *substitutes* and *sanitises* correctly, but the
**structural fidelity** is still broken: 272 subparts render the wrong input
widget, `\begin{array}` tables don't typeset, 33 questions collide on
re-import, shared stems leak into the first subpart, and 55 chapters/subjects
show as `Imported Chapter 46` placeholders. Every V2 polish surface and every
AI feature that reads this content is downstream of fixing it. This batch
closes five of the seven remaining gaps in the initiative's Definition of Done.

### PR 1 — M7-04 `RichContent` env detection + Skeleton
**Branch**: `feat/2026-05-31-richcontent-env`

- Files: `frontend_modern/src/shared/ui/renderRichContent.ts` (current logic;
  `grep` confirms **no** `\begin` / `ENV_RE` handling today),
  `RichContent.tsx`, `RichContent.test.tsx`, `index.ts`, plus the four consumers
  (`features/student/QuestionCard.tsx`, `features/student/SRSDrillPage.tsx`,
  `features/teacher/QuestionBankPage.tsx`, `features/teacher/CreateQuestionPage.tsx`).
- Add env detection in the chunk scanner:
  ```ts
  // Un-delimited LaTeX environments → one block-math chunk.
  // Non-greedy with a back-reference; Cabinet envs don't nest.
  const ENV_RE = /\\begin\{([a-zA-Z*]+)\}[\s\S]*?\\end\{\1\}/g;
  ```
  Insert ENV hits at **higher priority** than `$…$`/`\(…\)` so an environment
  embedded in a paragraph renders as a single math block, not partial inline
  matches.
- DOMPurify allowlist: add `table, thead, tbody, tr, td, th` (Cabinet HTML
  tables); keep `<img>` `src` restricted to `http(s)` (sets up M7-06).
- Verify all four delimiters (`$…$`, `$$…$$`, `\(…\)`, `\[…\]`) are exercised
  by a test and actually flow through every consumer (the M7-01 wiring may have
  only covered `QuestionCard`).
- `Skeleton.tsx` already exists in `shared/ui/` — confirm it's exported from
  `index.ts` and used in the `AssignmentDetailPage` loading branch (replace any
  bare "Loading…").
- **Tests**: snapshot fixtures pulled from the 2026-05-30 audit —
  (a) `<div>…\(…\)…</div>` renders without literal tags;
  (b) bare `\begin{array}{c|lcr}…\end{array}` typesets;
  (c) HTML `<table>` + inline KaTeX both render. Plus a fuzz test that
  `ENV_RE` is safe on truncated/unterminated `\begin{`.
- **Verify**: `cd frontend_modern && npm run type-check && npm run lint && npm test`.
- **Risk**: greedy regex across nested envs — back-reference + non-greedy makes
  it safe for this corpus; the fuzz test guards regressions.

### PR 2 — M7-09 `infer_taxonomy_names`
**Branch**: `feat/2026-05-31-infer-taxonomy`

- New command `backend/openshiksha/apps/core/management/commands/infer_taxonomy_names.py`
  (separate from `import_cabinet_questions.py` — importer stays deterministic).
- New data file `backend/openshiksha/apps/core/data/ncert_toc.json`: canonical
  chapter list per `(board, standard, subject)` from the NCERT table of contents.
- Pipeline per `Imported Chapter %` / `Imported Subject %` placeholder:
  1. **Content signal** — concept tags already on the chapter's questions +
     top salient noun phrases from `question_text`/`solution_text` (strip LaTeX
     + stopwords).
  2. **NCERT cross-reference** — match the keyword set against `ncert_toc.json`
     for the known `(standard, subject)`.
  3. **LLM disambiguation (optional, last resort)** — only when (1)+(2) tie,
     call the existing Claude integration with a ≤10-token-out prompt. Guard
     behind `ANTHROPIC_API_KEY` presence; skip gracefully if absent.
- Flags: `--dry-run` (print rename map), `--apply` (write). Idempotent: skip
  chapters whose name no longer matches the placeholder pattern (never clobber
  human edits). Write audit log to
  `apps/core/data/inferred_taxonomy_<date>.json`.
- **Tests**: keyword extractor unit test (polynomials fixture → "Polynomials");
  NCERT match test (8th Maths + `linear-equations` → "Linear Equations in One
  Variable"); end-to-end on seeded DB → 0 `Imported Chapter %` remaining after
  `--apply`.
- **Verify**: `pytest apps/core/tests -k taxonomy`.

## F. Legacy analysis & improvement opportunities

- **Per-subpart type (M7-03)**: legacy Cabinet stored `type` per subpart;
  modern collapsed it to the parent Question. Restoring per-subpart fidelity is
  a *correctness restore*, not a new feature — and improves on legacy by also
  emitting a `compound` summary the legacy schema never had.
- **Tag identity (M7-05)**: legacy used MySQL composite paths for uniqueness;
  the modern importer over-simplified to a bare ID. The path-tag restores
  legacy uniqueness while keeping the modern single-DB design.
- **Taxonomy names (M7-09)**: legacy had names in MySQL we no longer have.
  Rather than demand a mapping file, infer from content + NCERT — strictly
  better than the placeholder status quo and re-runnable.
