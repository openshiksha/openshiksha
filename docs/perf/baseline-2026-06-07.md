# Frontend bundle baseline — 2026-06-07

First measurement for the **Performance Budget** initiative
(`docs/initiatives/performance-budget.md`). Every later PERF PR is measured as a
delta against this file.

## How to reproduce

```bash
cd frontend_modern
npm run build              # production build (this baseline)
npm run build:analyze      # also emits dist/stats.html (treemap)
```

## Pre-PERF-01 baseline (monolithic, no chunking)

A single entry chunk was emitted with no vendor split, no route-splitting, no
lazy KaTeX:

| Asset                       | Size      | Gzip      |
| --------------------------- | --------- | --------- |
| `dist/assets/index-*.js`    | 855.15 kB | 247.44 kB |
| `dist/assets/index-*.css`   |  74.95 kB |  16.81 kB |

Vite emitted a *500 kB chunk* warning for the entry.

## Post-PERF-01 (this PR — vendor `manualChunks` only)

Vendor framework code is now split into long-cacheable chunks so feature code
can change without re-downloading React, react-query, KaTeX, or DOMPurify. **No
app code paths were touched** — same modules are loaded on first paint; they're
just chunked.

| Asset                           | Size      | Gzip      |
| ------------------------------- | --------- | --------- |
| `dist/assets/index-*.js`        | 353.05 kB |  91.53 kB |
| `dist/assets/vendor-react-*.js` | 223.93 kB |  71.67 kB |
| `dist/assets/vendor-katex-*.js` | 257.55 kB |  77.30 kB |
| `dist/assets/vendor-query-*.js` |  43.27 kB |  13.23 kB |
| `dist/assets/vendor-dompurify-*.js` | 24.98 kB |  9.81 kB |
| `dist/assets/rolldown-runtime-*.js` |   0.69 kB |   0.42 kB |
| `dist/assets/index-*.css`       |  46.11 kB |   8.74 kB |
| `dist/assets/vendor-katex-*.css`|  28.83 kB |   7.92 kB |

**Entry-chunk JS:** 855 kB → 353 kB (uncompressed) / 247 kB → 92 kB (gzip).

Total *transferred* bytes on a cold first load are slightly higher because the
runtime chunk is now itself a fetched file, but the cache hit rate on repeat
visits is dramatically better: the ~550 kB of vendor JS is now keyed by its own
content hash and survives any feature-code change.

## What this PR did NOT do

- **PERF-03** (route-level `React.lazy`) is the next PR and will further shrink
  the entry chunk by deferring teacher / admin / parent / dev-only pages.
- **PERF-04** (lazy KaTeX) will move the 257 kB `vendor-katex` chunk off the
  first-paint critical path entirely for non-math routes.
- **PERF-06** will lock the post-cut size in with a CI budget guard.

## Visualizer

`npm run build:analyze` writes `dist/stats.html` — open it in a browser to see
the gzip/brotli treemap. The visualizer plugin is only active when
`--mode analyze` is passed, so the default `npm run build` is unaffected.
