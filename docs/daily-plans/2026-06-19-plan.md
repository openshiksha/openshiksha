## B. Why this matters

- **Mission-core for K-12 India.** OpenShiksha serves students, teachers, and
  parents across a huge ability and device range — low-vision users, keyboard-only
  users, screen-reader users, and budget Android browsers. Accessibility is not
  polish here; it is access. The platform already commits to "Accessible by default"
  (V2 design principle #7, `2026-design-system-v2.md:51`) — this initiative makes
  that claim **measured and enforced** rather than aspirational.
- **The board explicitly asked for this.** STATUS.md's close-out for Mobile Shell
  names three candidate next bets: AI-tutor rebase (~5k-line diverged branch — *not
  atomic*, fails the "small reviewable PR" rule), an `/ai/predictions/` teacher
  surface (an explicit **product** call, deferred), and a **formal accessibility
  audit (WCAG 2.1 AA)**. Of the three, only the a11y audit decomposes into a clean
  batch of independent, low-risk, frontend-only PRs — exactly the shape this routine
  ships. The backlog entry (`STATUS.md:237-240`) already scopes it: "full audit
  (keyboard walkthrough, screen-reader spot-check, axe-core CI)."
- **The runway is already built — we're activating it, not inventing it.** The repo
  already has `@axe-core/playwright` + `axe-core` as devDeps, an `e2e/a11y.spec.ts`
  that runs axe on `/design`, and a CI `frontend-e2e` job that runs it and uploads
  the report. But the spec is **reporting-only** (`FAIL_ON_BLOCKING = false`) and
  covers **one** route. M6-01 (#202) shipped a *focused baseline* (skip link, dialog
  semantics, alt parity) and **explicitly deferred** the full audit "for a dedicated
  a11y initiative." This is that initiative. We extend coverage, fix, and gate.
- **Lowest-risk, purely-frontend, compounding.** No backend, no schema, no new
  runtime dependency (jsx-a11y is dev-only; axe is already present). Each PR is a
  bounded, independently-shippable change behind the existing CI guards. The work
  rides shipped infra (Playwright e2e job, axe artifact upload, the V2 token system,
  the LA i18n registry) and the new per-route axe harness + lint gate are reusable
  for every future surface.

## D. Concrete implementation plan

### A11Y-1 — Initiative doc + per-route axe baseline *(New, build first)*

**Docs.**
- New `docs/initiatives/2026-accessibility-wcag-aa.md`. Mirror the structure of
  `2026-mobile-shell-pwa-offline.md`:
  - **North Star:** "Every public and student-core surface passes axe-core WCAG 2.1
    AA with zero serious/critical violations, enforced in CI; keyboard-only and
    screen-reader users can complete the core journeys."
  - **Why now / what exists:** cite M6-01 (#202) focused baseline, the existing
    `e2e/a11y.spec.ts` reporting harness, the CI `frontend-e2e` job.
  - **Definition of Done (phased):** (1) per-route axe baseline measured; (2) static
    jsx-a11y lint gate; (3) public surfaces remediated to zero blocking + **gated**;
    (4 — future batch) student core-loop surfaces remediated + gated; (5 — future)
    keyboard-walkthrough + screen-reader spot-check sign-off; (6 — future) teacher/
    parent surfaces.
  - **Batch 1 = A11Y-1..5** (this plan). Leave a ledger table (filled by A11Y-5).

**Frontend (test harness).**
- Refactor `frontend_modern/e2e/a11y.spec.ts` to iterate a route table:
  ```ts
  const ROUTES = [
    { name: 'home', path: '/' },
    { name: 'login', path: '/login' },
    { name: 'register', path: '/register' },
    { name: 'register-school', path: '/register/school' },
    { name: 'register-open', path: '/register/open' },
    { name: 'enquire', path: '/enquire' },
    { name: 'design', path: '/design' },
  ];
  ```
  - For each route, a `test(name, …)` that navigates, waits for `document.fonts.ready`
    + the `h1`, runs `AxeBuilder().withTags(['wcag2a','wcag2aa','wcag21a','wcag21aa'])`,
    and writes `axe-report/<name>.json` (summary + violations), logging the
    by-impact counts. Keep `FAIL_ON_BLOCKING = false` for this PR.
  - Keep `/design`'s known-noise documentation (intentional low-contrast swatches,
    sandboxed widget iframe) — `/design` may stay reporting-mode longer than the
    auth/public routes because the showcase deliberately renders edge cases.
- Update the CI artifact step note (it already uploads `axe-report/`) — confirm the
  glob covers the new per-route files (it uploads the dir, so likely no change).

**Verify.** `npm run test:e2e -- a11y` locally (or rely on CI's `frontend-e2e`);
inspect the generated `axe-report/*.json` to build the fix list for A11Y-3/4. The
spec is non-gating so CI stays green regardless of findings.

**What could go wrong.** Some routes (`/register/school`, `/register/open`) may need
a query param or render a join-code step — confirm they render a stable `h1` before
the axe scan, or wait on a route-specific selector. Don't let a flaky wait turn a
reporting spec into a CI failure; prefer `waitForLoadState('networkidle')` +
`fonts.ready`.

### A11Y-2 — `eslint-plugin-jsx-a11y` static gate *(New, independent)*

**Frontend (lint config).**
- `npm i -D eslint-plugin-jsx-a11y` (dev-only; no runtime/bundle impact).
- Wire it into `frontend_modern/eslint.config.js` (flat config). Add the plugin and
  spread its `flat.recommended` rules onto the `**/*.{ts,tsx}` block (the repo uses
  the new flat-config plugin export shape).
- Run `npm run lint`. The config enforces `--max-warnings 0`, so **every** rule that
  fires must be either **fixed in this PR** or **explicitly downgraded** with a
  one-line rationale comment. Expected catches and the fix posture:
  - `alt-text`, `anchor-has-content`, `label-has-associated-control`,
    `role-supports-aria-props`, `no-redundant-roles` → **fix**.
  - `click-events-have-key-events` / `no-static-element-interactions` on genuinely
    non-interactive decorative handlers → downgrade to `warn` **only** with a
    tracked rationale, or refactor to a `<button>`; prefer the refactor where cheap.
- Scope the diff: fix the lint hits this PR surfaces, but **do not** opportunistically
  refactor unrelated logic. If the hit count is large (>~15 files), split the noisiest
  rule's fixes into a follow-up A11Y-2b and land the plugin with that one rule at
  `warn` — note the decision in the change doc.

**Verify.** `npm run lint` green at `--max-warnings 0`; `npx tsc --noEmit`;
`npm run test`; `npm run build` (entry chunk unchanged — dev-only dep).

**What could go wrong.** jsx-a11y on a mature codebase can surface dozens of hits. The
escape hatch is the `warn`-with-rationale downgrade per noisy rule so the *gate lands*
even if not every rule is at `error` day one — the point is the ratchet exists and
tightens over future PRs. Don't disable the plugin wholesale.

### A11Y-3 — Form-label, landmark & heading-order fixes *(Improve, soft-depends A11Y-1)*

**Frontend.** Target the structural axe findings (the `label`, `region`,
`landmark-unique`, `heading-order`, `page-has-heading-one` rule families) from the
A11Y-1 inventory on the auth/public surfaces:
- `features/auth/LoginPage.tsx`, `RegisterPage.tsx`, `RegisterSchoolPage.tsx`,
  `RegisterOpenPage.tsx`, `features/enquiry/EnquirePage.tsx`, `features/home/HomePage.tsx`.
- For each: every form control gets a programmatic label (`<label htmlFor={id}>` or
  `aria-label`/`aria-labelledby`); the page content sits in a single `<main>` (or the
  shared `#main-content` landmark from M6-01 — confirm public routes that *don't* use
  `AppShell` still expose one `<main>`); heading levels don't skip (no `h1`→`h3`); each
  page has exactly one `h1`.
- Reuse existing LA i18n keys for any visible label text; if a label was previously
  visual-only (placeholder as label is an anti-pattern), add a real localized label
  in en/hi/mr (the key-parity guard enforces all three).

**Verify.** Re-run the A11Y-1 axe spec locally and confirm the structural violation
families drop to zero on these routes; `npm run test`/`lint`/`tsc`/`build`. Existing
`LoginPage.test.tsx` and any auth tests must still pass.

**What could go wrong.** Adding visible labels can shift layout — keep the V2 form
chrome (`.input-brand`, `Input`/`Textarea`/`Select` primitives) and prefer
`sr-only` labels only where a visible label is genuinely redundant with adjacent
text. New i18n keys must land in all three locales in the same PR.

### A11Y-4 — Colour-contrast remediation on V2 tokens *(Improve, independent)*

**Frontend.** Fix the axe `color-contrast` failures (typically the largest single
bucket):
- From the A11Y-1 inventory, list every element failing 4.5:1 (normal) / 3:1 (large).
  Common culprits: muted body text (`text-ink-400`/`text-ink-500` on `bg-paper`),
  brand button label contrast (`text-white` on lighter `brand-` shades), badge tones
  (rose/amber/emerald `*-600` text on `*-50` fills), placeholder text, and disabled
  states.
- Prefer **fixing usage** (bump `ink-400`→`ink-500/600` for body copy; ensure brand
  buttons use a shade that clears 4.5:1 with white) over editing the palette — but if
  a token's defined shade is *itself* failing in its intended role, adjust the shade in
  `tailwind.config` and re-verify no regressions on `/design`.
- Add a short **"contrast rules"** subsection to `2026-design-system-v2.md` (or the new
  a11y doc) recording the minimum-contrast token-usage guidance so future surfaces
  don't reintroduce the failures.

**Verify.** Re-run axe on the affected routes; `color-contrast` blocking count → 0 on
the public routes. Eyeball `/design` to confirm no visual regression. `npm run build`.

**What could go wrong.** Contrast fixes can subtly shift the V2 "warm paper/ink"
aesthetic — keep changes minimal and within the existing palette family; don't
introduce new colours. The `/design` showcase intentionally renders low-contrast
swatches as *examples* — exclude those from the fix (they're documented known-noise,
not real UI), which is why `/design` stays reporting-mode in A11Y-5.

### A11Y-5 — Gate the clean public routes + close-out *(New gate + Docs, build last)*

**Frontend (gate).**
- In `e2e/a11y.spec.ts`, introduce a per-route `gate` flag. For the routes A11Y-3/4
  cleaned (`/`, `/login`, `/register*`, `/enquire`), set `gate: true` and assert
  `blocking === []` (serious/critical). Keep `/design` `gate: false` (documented
  known-noise) until its swatches are excluded or annotated.
- This makes the public surfaces **regression-proof**: any future PR that reintroduces
  a serious/critical WCAG AA violation on a gated route fails CI's `frontend-e2e` job.

**Docs.**
- `docs/changes/2026-06-19-a11y-batch1.md`: what changed across A11Y-1..5, the
  per-route harness contract, the jsx-a11y ruleset decisions, the contrast rules, and
  which routes are now gated vs. still reporting.
- `docs/perf/` (or `docs/a11y/`) **manual checklist**: keyboard-only walkthrough of the
  public journeys (tab order, focus-visible, ESC/Enter on interactive controls) and a
  screen-reader spot-check note (NVDA/VoiceOver) — mirror the prior PWA manual-test docs.
- Fill the **ledger table** in `2026-accessibility-wcag-aa.md` — a row per A11Y PR.
- Update **`STATUS.md`**: add the Accessibility initiative as the new **#1 Active**
  bet, record "Batch 1 (A11Y-1..5) shipped 2026-06-19," and note the next phase
  (student core-loop surfaces → gate; then keyboard/SR sign-off). Move the old "no
  unblocked next bet" note into history.

**Verify.** `npm run test:e2e` green with the new gates (the fixes must have landed
first); docs read back correctly; key-parity + build CI green.

**What could go wrong.** Don't flip a route's gate until its fixes (A11Y-3/4) actually
merged — if one slips, leave that route reporting-mode and note it. Gating a still-dirty
route would red-wall CI. Verify the gate by intentionally checking the axe report shows
zero blocking for each gated route before flipping.

## F. Legacy analysis & improvement opportunities

- **Legacy had no accessibility story at all.** Django 1.11 server-rendered templates
  with hand-rolled forms, no ARIA, no contrast discipline, no automated checking.
  Keyboard and screen-reader users were unsupported. There is nothing to *port* —
  this is **net-new platform capability**.
- **What to preserve from the modern app:** the M6-01 foundation (skip link,
  `#main-content` landmark, dialog pattern) and the V2 "Accessible by default"
  principle. We build *on* them rather than redoing them.
- **What to improve:** turn "accessible by default" from an aspiration into a
  **measured, CI-enforced contract**. axe in reporting-mode on one route becomes a
  per-route baseline + a static lint gate + a runtime regression gate on the public
  surfaces. This is the standard modern ed-tech bar (axe-core CI is table stakes for
  any platform claiming AA) and the legacy system never approached it.
- **Found en route:** several `features/*` files already carry partial `aria-*`
  usage (grep hit ~15 files) — evidence of ad-hoc a11y work that a static gate +
  per-route audit will now make consistent and regression-proof.
