## F. Legacy analysis & improvement opportunities

These surfaces have **no legacy UX worth preserving** — the Django 1.11 app used
server-rendered Bootstrap/blue templates with full page reloads.

- **Browse / Learning Path:** legacy had no self-directed "browse the question bank
  and practice" path at all — this is net-new modern capability. V2 makes it feel
  like a deliberate learning surface, and LearningPath is the perfect home for the
  "progress = unlocking" motif the whole brand is built on.
- **Teacher authoring:** legacy authoring lived in `sphinx/` (server forms → saved
  to the Cabinet filesystem service). The modern in-DB authoring with a live
  LaTeX/HTML preview (#M7-01) and AI generation (#185) is already a large
  improvement; V2 makes it look like a first-class product tool, not a CRUD form.
- **Teacher assignment detail / class panels:** legacy gave teachers a static
  gradebook. The modern class-health + weekly-report panels are richer; V2 makes
  them *credible at a glance*, reinforcing teacher trust.
- **Improvement lever for all five:** every page swaps hand-rolled inputs/cards/
  pills for `ui/` primitives, so the system gets cheaper to extend each session —
  the initiative's explicit compounding goal. After this batch, **no authenticated
  page hand-rolls a form field or status pill.**
