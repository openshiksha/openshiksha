### Priority 1: Ship Working-Tree Changes + Fix Submission Filter

**Bug to fix first (`backend/openshiksha/apps/api/views/core.py`):**

The `SubmissionViewSet` has no filter backend. `GET /api/submissions/?assignment=1` returns all of the student's submissions — the `?assignment=` param is silently ignored.

Fix: add `django-filter` (already in requirements or standard DRF) and a `filterset_fields`:

```python
from django_filters.rest_framework import DjangoFilterBackend

class SubmissionViewSet(viewsets.ModelViewSet):
    filter_backends = [DjangoFilterBackend]
    filterset_fields = ['assignment']
    ...
```

Or, simpler and dependency-free: override `get_queryset` to read the query param manually:

```python
def get_queryset(self):
    qs = super().get_queryset()  # base already applies role filter
    assignment_id = self.request.query_params.get('assignment')
    if assignment_id:
        qs = qs.filter(assignment_id=assignment_id)
    return qs
```

**Verify (critical security check):** After fixing, confirm that a student cannot see another student's submission by passing a different student's assignment_id. The base `get_queryset` already restricts to `student=user` so this is safe — but test it explicitly.

## F. Legacy Analysis & Improvement Opportunities

### Question content (QuestionSubpart.question_text)
- **Legacy did**: Questions had text in a separate `cabinet` question bank, linked by ID. Content was not stored in Django models — it was fetched from cabinet at render time.
- **What was good**: Separation of question content from assignment metadata. Question text could be updated without touching models.
- **What was limited**: Tightly coupled to the cabinet service; offline/demo mode was impossible; no content versioning.
- **How we improved**: Storing `question_text` + `options` directly on `QuestionSubpart`. For production, these can be populated from cabinet on import. For demo/development, seed data can contain real content. This makes the platform self-contained.

### Assignment detail / student answer submission
- **Legacy did**: Django template rendering questions per-page, form POST for each answer, server-side session tracking. No auto-save.
- **What was limited**: Full page reload per answer; no draft saving; poor mobile UX; no real-time feedback.
- **How we improved**: Single-page React with debounced auto-save (2s), optimistic UI, KaTeX for math rendering, answer state persisted in Submission.answers JSON field.

### Teacher assignment creation
- **Legacy did**: Django admin or custom teacher portal with server-rendered forms.
- **What was limited**: Admin panel not suitable for end-user teachers; no API to enable future mobile app.
- **How we improve**: API-first React form. Same POST `/api/v1/assignments/` endpoint can be used by future mobile apps.
