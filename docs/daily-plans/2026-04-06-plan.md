### Priority 1: Croupier Phase 2 — Variable Substitution

#### Overview

`variable_constraints` is a JSONField on `QuestionSubpart` describing named variables with numeric ranges:

```json
{
  "a": {"min": 2, "max": 9, "integer": true},
  "b": {"min": 1, "max": 20, "integer": true},
  "c": {"min": 10, "max": 50, "integer": true}
}
```

At **question-serve time** the croupier substitutes `{{a}}`, `{{b}}`, `{{c}}` tokens in `question_text` and `options[].text` using a deterministic seed per `(student_id, subpart_id)`. At **grading time** the grader re-derives the same variable values from the same seed and evaluates the `correct_answer["answer"]` expression against them.

The seed namespace is distinct from Phase 1: `f"{student_id}:{subpart_id}:vars"` so MCQ shuffling and variable substitution never interfere.

```python
def _make_var_seed(student_id: int, subpart_id: int) -> int:
    """Distinct seed namespace for variable substitution (Phase 2)."""
    seed_str = f"{student_id}:{subpart_id}:vars"
    return int(hashlib.sha256(seed_str.encode()).hexdigest(), 16) % (2**32)


def sample_variable_values(
    variable_constraints: dict,
    student_id: int,
    subpart_id: int,
) -> dict:
    """
    Sample variable values deterministically for a (student, subpart) pair.

    Returns {"a": 3, "b": 14, "c": 27} for the given constraints.
    Same inputs always produce the same output.
    """
    seed = _make_var_seed(student_id, subpart_id)
    rng = random.Random(seed)
    values = {}
    for name, spec in variable_constraints.items():
        lo, hi = spec["min"], spec["max"]
        is_int = spec.get("integer", True)
        decimals = spec.get("decimals", 2)
        if is_int:
            values[name] = rng.randint(int(lo), int(hi))
        else:
            raw = rng.uniform(float(lo), float(hi))
            values[name] = round(raw, decimals)
    return values


def substitute_variables(text: str, variable_values: dict) -> str:
    """Replace {{var}} tokens in text with their sampled values."""
    for name, val in variable_values.items():
        text = text.replace(f"{{{{{name}}}}}", str(val))
    return text


def substitute_variables_for_student(
    question_text: str,
    options: list[dict] | None,
    variable_constraints: dict | None,
    student_id: int,
    subpart_id: int,
) -> tuple[str, list[dict] | None, dict]:
    """
    Apply variable substitution to question_text and options.

    Returns (substituted_text, substituted_options, variable_values).
    variable_values is needed by the grader to evaluate correct_answer expressions.
    If variable_constraints is None or empty, returns inputs unchanged.
    """
    if not variable_constraints:
        return question_text, options, {}

    variable_values = sample_variable_values(variable_constraints, student_id, subpart_id)
    subst_text = substitute_variables(question_text, variable_values)
    subst_options = None
    if options:
        subst_options = [
            {"key": opt["key"], "text": substitute_variables(opt["text"], variable_values)}
            for opt in options
        ]
    return subst_text, subst_options, variable_values
```

**Safe expression evaluator** — Add to `croupier.py` (used by grader, not by question-serve):

```python
import ast
import operator as _op

_SAFE_OPS = {
    ast.Add: _op.add,
    ast.Sub: _op.sub,
    ast.Mult: _op.mul,
    ast.Div: _op.truediv,
    ast.Pow: _op.pow,
    ast.USub: _op.neg,
    ast.UAdd: _op.pos,
}


def _eval_ast_node(node):
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in _SAFE_OPS:
        return _SAFE_OPS[type(node.op)](_eval_ast_node(node.left), _eval_ast_node(node.right))
    if isinstance(node, ast.UnaryOp) and type(node.op) in _SAFE_OPS:
        return _SAFE_OPS[type(node.op)](_eval_ast_node(node.operand))
    raise ValueError(f"Unsafe or unsupported expression node: {type(node).__name__}")


def safe_eval_expr(expr: str, variable_values: dict) -> float:
    """
    Safely evaluate an arithmetic expression string with variable substitution.

    e.g. safe_eval_expr("({{c}} - {{b}}) / {{a}}", {"a": 3, "b": 5, "c": 20}) → 5.0

    Uses ast.parse — does NOT use eval(). Only supports +, -, *, /, **, unary -.
    Raises ValueError for unsupported operations or malformed expressions.
    """
    interpolated = substitute_variables(expr, variable_values)
    tree = ast.parse(interpolated, mode="eval")
    return float(_eval_ast_node(tree.body))
```

```python
class QuestionMistakeViewSet(viewsets.ReadOnlyModelViewSet):
```

## F. Legacy Analysis & Improvement Opportunities

### Variable Substitution (Croupier Phase 2)

**Legacy did**: The `croupier/` module substituted `{{ variable }}` tokens in question text using a seeded RNG per `(student_id, question_id)`. Variable definitions (min, max, step, type) were stored in the Cabinet CMS — not in Django. The correct answer was a Python expression string evaluated server-side via raw `eval()`.

**What was good**: Completely neutralized copying on numeric homework. Teachers could write one question template and it generated a unique variant per student. Used extensively for algebra and arithmetic assignments.

**What was limited**: (a) Variable definitions were in Cabinet, not Django — impossible to seed or test without the Cabinet service running. (b) Raw `eval()` is a security vulnerability — any expression a teacher typed was executed verbatim. (c) No authoring preview: teachers couldn't see sample substitutions before publishing. (d) Tightly coupled to legacy question format, not portable.

**How we improve**:
- Variables stored in `QuestionSubpart.variable_constraints` JSONField — no Cabinet, fully testable, seedable in `seed_demo_data`
- `safe_eval_expr` uses `ast.parse` + restricted operator whitelist — no `eval()`, no security risk
- Authoring UI shows live preview: auto-detect `{{var}}` tokens as teacher types, show three sample substitution previews inline

### Question-Difficulty Analytics

**Legacy did**: `edge/` tracked `regression` per question per SubjectRoom (same concept). But legacy had no teacher-facing UI — only Django admin.

**How we improve**: Surface in-context at the assignment level — teachers see question difficulty directly on the assignment detail page, ranked by how much the class struggled. No admin required. Difficulty shown as a relative progress bar (normalized to class maximum) rather than a raw float.

### Adaptive Learning Path

**Legacy did**: Nothing — no learning path concept existed. Students worked through teacher-assigned problem sets sequentially with no adaptive sequencing.

**How we improve**: SM-2 spaced repetition + mastery tracking + learning gap detection combine to build a personalized, step-by-step study roadmap per student per subject room. The page makes the invisible AI work visible — students see exactly where they are in their learning sequence and what to do next. This is a product differentiator no Indian K-12 platform currently offers.

```
1. Login as teacher → Create Question page
   - Create a numeric question: "Solve {{a}}x + {{b}} = {{c}}. Find x."
   - Variable Constraints UI auto-detects {{a}}, {{b}}, {{c}}
   - Set constraints: a: {min:2, max:9}, b: {min:1, max:20}, c: {min:10, max:50}
   - Correct answer: "({{c}} - {{b}}) / {{a}}"
   - Save question

2. Build problem set with that question → Create assignment for class

3. Login as student1 → Open assignment
   - Verify question text shows substituted values (e.g. "Solve 3x + 7 = 25")
   - Compute correct answer manually → submit

4. Login as student2 → Open same assignment
   - Verify DIFFERENT values from student1

5. Login as teacher → Assignment detail
   - "Hardest Questions" section appears below submission table
   - Shows regression data for the variable question

6. Login as student → StudentDashboard
   - After grading, "View Learning Path →" link appears in RecommendationsPanel

7. Student → /student/learning-path
   - Learning path page shows ordered steps
   - First incomplete step is highlighted with "→ Start"
```
