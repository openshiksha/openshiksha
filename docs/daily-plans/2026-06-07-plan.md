# OpenShiksha Daily Plan — 2026-06-07

## A. Today's objective

Promote and kick off a new top initiative — **Performance Budget** — and ship
its first batch. Make the K-12 student's first paint fast by route-splitting
the 770 kB monolithic JS bundle, dropping dead weight, and locking the win in
with a CI budget guard. The most important outcome: a dramatically smaller
**entry chunk**, measured before-and-after, that CI then defends.

## B. Why this matters

V2 "Chalk & Unlock", Cabinet Data Fidelity, and Legacy Feature-Parity are all
**closed**; Interactive Widgets is **paused after IW-8** (product discovery
gate on Widget Studio). The app is feature-complete but **not yet fast** — the
biggest standing quality gap. The Vite build prints `dist/assets/index-*.js
770 kB`, and `src/App.tsx` statically imports all ~30 route pages plus KaTeX
into one chunk. A student opening *login* currently downloads the entire
teacher authoring surface, admin classroom manager, the dev-only widget
playground, and the math engine before they can type a password. On the actual
target network (budget Android on Indian 2G/3G), that's seconds of blank
screen. This batch directly serves the core educational mission: the platform
is only useful if students can *reach* it.

New initiative doc: [`docs/initiatives/performance-budget.md`](../initiatives/performance-budget.md).

## D. Concrete implementation plan

### PERF-01 — Measurement harness + vendor `manualChunks`
- **Files:** `frontend_modern/vite.config.ts`, `frontend_modern/package.json`
  (add `rollup-plugin-visualizer` devDep + `"build:analyze"` script),
  `docs/perf/baseline-2026-06-07.md` (new).
- **What to change:** under `build`, add
  `rollupOptions.output.manualChunks` mapping `react`/`react-dom`/
  `react-router-dom` → `vendor-react`, `@tanstack/react-query` →
  `vendor-query`, `katex` → `vendor-katex`, `dompurify` → `vendor-dompurify`.
  Add the visualizer plugin **only** under an analyze flag (e.g. gated on
  `process.env.ANALYZE`) so normal builds aren't slowed. Set
  `chunkSizeWarningLimit` to the honest current number and note it.
- **New rationale:** vendor code changes rarely; splitting it improves
  long-term caching *before* route-splitting even lands, and the baseline doc
  gives every later PR a measurable delta.
- **Dependencies:** none — do first.
- **Verify:** `npm run build` succeeds and emits separate `vendor-*` chunks;
  `ANALYZE=1 npm run build:analyze` writes `dist/stats.html`; baseline doc
  records per-chunk gzip sizes.
- **What could go wrong:** a `manualChunks` cycle warning — keep groups
  coarse (framework vs. feature), don't over-split.

### PERF-02 — Remove unused `recharts`
- **Files:** `frontend_modern/package.json` (remove `"recharts"`),

- **Verify:** `grep -rn "recharts" frontend_modern/src` empty (already true);

### PERF-03 — Route-level code-splitting (`React.lazy`)
- **Files:** `frontend_modern/src/App.tsx`.
- **Keep eager:** `LoginPage`, `RegisterPage`, `RegisterSchoolPage`,
  `RegisterOpenPage`, `HomePage`, `AppShell`, `ProtectedRoute`,
  `LoadingSpinner`, `ErrorBoundary`, `NotFoundPage`, `UserRole` (type).
- **Make lazy** (named-export shim
  `lazy(() => import('...').then(m => ({ default: m.X })))`):
  `StudentDashboard`, `AssignmentDetailPage`, `ProficiencyPage`,
  `LearningPathPage`, `SRSDrillPage`, `BrowsePage`, `BrowsePracticePage`,
  `ProfilePage`, `TeacherDashboard`, `CreateAssignmentPage`,
  `CreateQuestionPage`, `CreateProblemSetPage`, `TeacherAssignmentDetailPage`,
  `QuestionBankPage`, `ParentDashboard`, `ParentInsightsPage`,
  `ParentInsightsLandingPage`, `AdminDashboard`, `ClassroomManagePage`,
  `EnquirePage`, **`DesignSystemPage`**, **`WidgetDevPage`** (dev pages must
  never be in a student's first load).
- **Wrap** the `<Routes>` element in a single
  `<Suspense fallback={<LoadingSpinner />}>` inside `<Router>`.
- **Verify:** `npm run build` shows the entry chunk shrink sharply and many
  small per-route chunks appear; `npm test` green (Vitest resolves Suspense);
  `npx playwright test` smoke nav passes; record before/after entry-chunk
  size in the change doc.
- **What could go wrong:** a named-export typo → blank route (mitigate: one
  shared Suspense + verify each route renders); React throwing on a missing
  boundary (mitigate: single top-level boundary covers all).

### PERF-04 — Lazy-load KaTeX
- **Files:** `frontend_modern/src/shared/ui/renderRichContent.ts` and/or
  `RichContent.tsx`.
- **Approach:** convert the static `katex` import into a cached dynamic
  `import('katex')` triggered on first math render, OR wrap `RichContent` in a
  `React.lazy` boundary. Render the raw/plain-text fallback until KaTeX
  resolves so there's no blank flash.
- **Verify:** `dist/stats.html` shows a math-free route (e.g. a dashboard) no
  longer pulls the KaTeX chunk on first load; math still renders on
  `AssignmentDetailPage` and the `CreateQuestionPage` preview; `RichContent`
  tests green (may need a `findBy*`/`waitFor` for the async path).
- **What could go wrong:** existing synchronous `RichContent` tests assume
  immediate KaTeX output — update them to await the async render.

### PERF-06 — CI bundle-size budget guard
- **Files:** `frontend_modern/scripts/check-bundle-budget.mjs` (new) +
  `frontend_modern/scripts/check-bundle-budget.test.mjs` (new, Vitest pattern
  already wired for `scripts/**`), `frontend_modern/package.json` (a
  `"check:budget"` script), the GitHub Actions frontend workflow (add a step
  after `npm run build`), `docs/perf/budget.md` (new).
- **Logic:** read `dist/assets/*.js`, find the entry chunk (the one referenced
  by `dist/index.html`), compare its size to a `BUDGET_BYTES` const set just
  above the post-PERF-03 measured size with headroom; exit non-zero + print
  the chunk + over-budget delta on failure.
- **Verify:** passes on the current post-cut build; a unit test feeds a
  synthetic oversized chunk and asserts a non-zero exit; document how to raise
  the ceiling deliberately.
- **What could go wrong:** entry-chunk filename is hashed — resolve it from
  `index.html`, don't hard-code the name.

## F. Legacy analysis & improvement opportunities

This initiative has **no legacy analogue** — the legacy Django-template
`frontend/` was server-rendered, so "bundle size" wasn't a concept; pages were
full HTML round-trips. The modern SPA traded round-trips for a single download,
which is the right architecture **only if** that download is split. The legacy
system's implicit "you only fetch the page you're on" property is exactly what
route-level code-splitting restores in the SPA world — best of both: SPA
interactivity *and* per-route payloads. This is a pure **Improve** batch, not
a port.
