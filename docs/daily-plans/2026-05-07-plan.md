This plan picks up where the roadmap left off, targeting the three highest-value unbuilt features: a browsable teacher question bank, a student SRS review panel, and a parent dashboard.

---

## A. Today's Objective

Surface three long-overdue UX gaps: give teachers a browsable question library, make the spaced repetition engine visible to students, and make the parent role functional for the first time.

---

## B. Why This Matters

- **Teacher Question Bank**: Teachers can create questions but have no way to browse or reuse them from the UI. Without a list view, every assignment workflow requires remembering question IDs or opening Django admin. This is the most glaring daily-use gap in the teacher flow.
- **SRS Review Panel**: The SM-2 spaced repetition engine writes `SpacedRepetitionEntry` records with `next_review_date` and exposes a `/api/ai/spaced-repetition/due/` endpoint. Students never see any of this. The platform's most sophisticated adaptive learning feature is completely invisible.
- **Parent Dashboard**: The `parent` role exists in the User model, auth system, and Navbar ROLE_LABELS — but parents who log in see nothing. The role is a dead end. Activating parent access closes a major product gap and adds a stakeholder audience (parents as engagement drivers).

```typescript
import { useQuery } from '@tanstack/react-query';
import { apiClient } from '@/api/client';

export interface SRSEntry {
  id: number;
  knowledge_node: number;
  chapter_name: string;
  interval_days: number;
  easiness_factor: number;
  repetitions: number;
  next_review_date: string;  // YYYY-MM-DD
  last_reviewed_at: string | null;
}

const fetchDueEntries = async (): Promise<SRSEntry[]> => {
  const { data } = await apiClient.get<SRSEntry[]>('/ai/spaced-repetition/due/');
  // The /due/ action returns a plain array, not paginated
  return Array.isArray(data) ? data : (data as any).results ?? [];
};

export const useSpacedRepetitionDue = () =>
  useQuery<SRSEntry[]>({
    queryKey: ['srs', 'due'],
    queryFn: fetchDueEntries,
    staleTime: 10 * 60 * 1000,  // 10 min — SRS schedule changes slowly
  });
```

#### Step 2 — New `DueForReviewPanel.tsx`

**New file**: `frontend_modern/src/features/student/DueForReviewPanel.tsx`

Design:
- Panel only renders when there are due entries (hidden otherwise)
- Overdue entries (next_review_date < today) shown with red accent
- Due today shown with amber accent
- Upcoming (due in 1–3 days) shown with blue/neutral
- Each row: chapter name, due date label, interval badge ("Review every N days"), repetitions count ("Reviewed N times")
- No action button yet (spaced repetition workflow requires teacher-assigned problem sets — that's future work). Just surface the information.

```tsx
import { useSpacedRepetitionDue } from './useSpacedRepetitionDue';
import type { SRSEntry } from './useSpacedRepetitionDue';

const today = () => new Date().toISOString().slice(0, 10);

const getUrgency = (nextReviewDate: string): 'overdue' | 'today' | 'soon' => {
  const t = today();
  if (nextReviewDate < t) return 'overdue';
  if (nextReviewDate === t) return 'today';
  return 'soon';
};

const URGENCY_STYLES = {
  overdue: { dot: 'bg-red-500', text: 'text-red-700', label: 'Overdue', bg: 'bg-red-50' },
  today: { dot: 'bg-amber-500', text: 'text-amber-700', label: 'Due today', bg: 'bg-amber-50' },
  soon: { dot: 'bg-blue-400', text: 'text-blue-700', label: 'Coming up', bg: '' },
};

const SRSRow = ({ entry }: { entry: SRSEntry }) => {
  const urgency = getUrgency(entry.next_review_date);
  const style = URGENCY_STYLES[urgency];
  const dueLabel =
    urgency === 'overdue'
      ? `Overdue since ${entry.next_review_date}`
      : urgency === 'today'
      ? 'Due today'
      : `Due ${entry.next_review_date}`;

  return (
    <div className={`flex items-center justify-between py-2.5 px-3 rounded-lg ${style.bg}`}>
      <div className="flex items-center gap-2 min-w-0">
        <span className={`shrink-0 w-2 h-2 rounded-full ${style.dot}`} />
        <div className="min-w-0">
          <p className="text-sm font-medium text-gray-900 truncate">{entry.chapter_name}</p>
          <p className={`text-xs ${style.text}`}>{dueLabel}</p>
        </div>
      </div>
      <div className="text-right shrink-0 ml-3">
        <p className="text-xs text-gray-500">every {entry.interval_days}d</p>
        <p className="text-xs text-gray-400">{entry.repetitions}× reviewed</p>
      </div>
    </div>
  );
};

export const DueForReviewPanel = () => {
  const { data: entries } = useSpacedRepetitionDue();

  if (!entries || entries.length === 0) return null;

  const sorted = [...entries].sort((a, b) => a.next_review_date.localeCompare(b.next_review_date));
  const overdueCount = sorted.filter((e) => getUrgency(e.next_review_date) === 'overdue').length;

  return (
    <div className="bg-white rounded-xl border border-amber-200 p-5">
      <div className="flex items-center justify-between mb-3">
        <h2 className="text-base font-semibold text-gray-900">
          Due for Review
          {overdueCount > 0 && (
            <span className="ml-2 text-xs font-semibold bg-red-100 text-red-700 px-2 py-0.5 rounded-full">
              {overdueCount} overdue
            </span>
          )}
        </h2>
        <span className="text-xs text-gray-400">{entries.length} topic{entries.length !== 1 ? 's' : ''}</span>
      </div>
      <div className="space-y-1.5">
        {sorted.slice(0, 5).map((e) => (
          <SRSRow key={e.id} entry={e} />
        ))}
        {entries.length > 5 && (
          <p className="text-xs text-center text-gray-400 pt-1">
            +{entries.length - 5} more topics
          </p>
        )}
      </div>
      <p className="text-xs text-gray-400 mt-3 pt-2 border-t border-gray-100">
        Practice your assignments to push review dates forward.
      </p>
    </div>
  );
};
```

#### Step 3 — Backend: Parent access to child proficiency

**File**: `backend/openshiksha/apps/api/views/core.py`

Modify `StudentProficiencyViewSet` to allow parents to read a specific child's proficiency:

```python
class StudentProficiencyViewSet(viewsets.ReadOnlyModelViewSet):
    serializer_class = StudentProficiencySerializer

    def get_permissions(self):
        # Students see their own; parents see their children's
        return [permissions.IsAuthenticated()]

    def get_queryset(self):
        user = self.request.user

        if user.role in (UserRole.STUDENT, UserRole.OPEN_STUDENT):
            return (
                StudentProficiency.objects.filter(student=user)
                .select_related(
                    "question_tag",
                    "subject_room__subject",
                    "subject_room__classroom__standard",
                )
                .order_by("subject_room__subject__name", "question_tag__name")
            )

        if user.role == UserRole.PARENT:
            child_id = self.request.query_params.get("student")
            if not child_id:
                return StudentProficiency.objects.none()
            # Security: only the parent's own children
            is_my_child = user.children.filter(id=child_id).exists()
            if not is_my_child:
                return StudentProficiency.objects.none()
            return (
                StudentProficiency.objects.filter(student_id=child_id)
                .select_related(
                    "question_tag",
                    "subject_room__subject",
                    "subject_room__classroom__standard",
                )
                .order_by("subject_room__subject__name", "question_tag__name")
            )

        return StudentProficiency.objects.none()
```

**Security note**: The ownership check `user.children.filter(id=child_id).exists()` ensures a parent can only access data for users in their `children` M2M relationship. An unauthenticated or non-parent user gets `none()` via the fallthrough. A parent who passes a child_id not in their family gets `none()`. No data leaks.

```tsx
interface SubjectGroup {
  subjectName: string;
  classroomDisplay: string;
  records: StudentProficiency[];
}

const groupBySubject = (records: StudentProficiency[]): SubjectGroup[] => {
  const map = new Map<string, SubjectGroup>();
  for (const r of records) {
    const key = `${r.subject_name}|${r.classroom_display}`;
    if (!map.has(key)) map.set(key, { subjectName: r.subject_name, classroomDisplay: r.classroom_display, records: [] });
    map.get(key)!.records.push(r);
  }
  return Array.from(map.values());
};

const ProficiencyBar = ({ record }: { record: StudentProficiency }) => {
  const pct = Math.round(record.score * 100);
  const barColor = pct >= 70 ? 'bg-green-500' : pct >= 40 ? 'bg-yellow-400' : 'bg-red-400';
  return (
    <div className="flex items-center gap-3 py-2">
      <div className="flex-1 min-w-0">
        <div className="flex items-baseline justify-between gap-2 mb-1">
          <span className="text-sm font-medium text-gray-800 truncate">{record.tag_name}</span>
          <span className="text-sm font-semibold text-gray-700 shrink-0">{pct}%</span>
        </div>
        <div className="h-2 bg-gray-100 rounded-full overflow-hidden">
          <div className={`h-full rounded-full transition-all ${barColor}`} style={{ width: `${pct}%` }} />
        </div>
        <p className="text-xs text-gray-400 mt-1">
          {record.tick_count} question{record.tick_count !== 1 ? 's' : ''} practised
        </p>
      </div>
    </div>
  );
};

const ChildView = ({ child }: { child: User }) => {

      </div>

  return (
    <div className="space-y-6">
      {groups.map((group) => (
        <div key={`${group.subjectName}|${group.classroomDisplay}`} className="bg-white rounded-xl border border-gray-200 p-5">

            ))}
          </div>
        </div>
      ))}
    </div>
  );
};

export const ParentDashboard = () => {

        <p className="text-sm text-gray-500 mt-1">Monitor your children's learning progress.</p>

      {/* Child selector (tabs for ≤4 children, dropdown otherwise) */}

          {children.map((child) => (
            <button
              key={child.id}
```

#### What could go wrong

- **`/users/me/children/` response shape**: The `@action` returns `Response(UserSerializer(kids, many=True).data)` — a plain array. The hook accounts for this. If DRF wraps it in pagination at some point, add `.results` fallback.
- **Empty `children` M2M**: Parent with no children linked → `useChildren` returns `[]` → empty state renders. Correct.
- **`?student=<id>` security**: The ownership check relies on `request.user.children.filter(id=child_id).exists()`. If `child_id` is not a valid integer (e.g., `?student=abc`), Django will raise `ValueError` on `filter(id=child_id)`. Add `try/except` or use `int(child_id)` with validation:
  ```python
  try:
      child_pk = int(child_id)
  except (ValueError, TypeError):
      return StudentProficiency.objects.none()
  is_my_child = user.children.filter(id=child_pk).exists()
  ```
- **`grade` field**: `UserSerializer` may not currently include `grade`. Verify and add if missing — it's on the `User` model.

## F. Legacy Analysis & Improvement Opportunities

### Teacher Question Management (Priority 1)

**Legacy**: Questions lived in an external Cabinet service. Teachers could browse through a Sphinx-provided UI that talked to Cabinet over HTTP. Sphinx was tightly coupled to Cabinet — no questions could be browsed offline. Question IDs were Cabinet resource paths (UUIDs), not database integers.

**Modern improvement**: Questions are in the PostgreSQL DB with Django ORM. Search, filter, and display are trivial REST operations. The `QuestionBankPage` gives teachers instant access to the full question corpus with fuzzy search, no Cabinet dependency. Future: add `search_fields = ["subparts__question_text"]` to `QuestionViewSet` to enable content search.

### Spaced Repetition (Priority 2)

**Legacy**: No spaced repetition system existed. Students practiced whatever was assigned; no adaptive review scheduling. Teachers had to manually identify struggling students from aggregate analytics.

**Modern improvement**: SM-2 algorithm runs in the AI pipeline, creates `SpacedRepetitionEntry` records with exponentially growing review intervals. The `DueForReviewPanel` makes this visible for the first time. Future: when a question from the student's SRS backlog appears in a newly assigned problem set, surface a "This is a review" badge (using `LearningPathStep.is_review`).

### Parent Engagement (Priority 3)

**Legacy**: No parent-facing interface existed. Parents could only receive SMS notifications (via Pylon) about assignment completion. No portal, no progress view, no drill-down.

**Modern improvement**: Full parent dashboard with per-child proficiency visualization, grouped by subject. The child selector handles multi-child families. Security is enforced at the API layer via ownership check on `children` M2M. Future: add assignment completion status (submitted/pending/overdue) per child, and push notification preferences for parents.
