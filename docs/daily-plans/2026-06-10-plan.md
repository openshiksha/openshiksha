## B. Why this matters

`/ai/assignment-drafts/` is a fully built, fully tested teacher feature —
generate → review rationale → approve into a real ProblemSet + Assignment —
with **zero frontend consumers**. Wiring it converts paid-for backend work into
the single highest-leverage teacher workflow we have (one click from "my class
is weak on X" to a targeted assignment). The two polish items kill the last
known instances of the "error masquerades as all-clear" anti-pattern (a failed
fetch must never tell a teacher their class is fine), and ASA-8/9 make the SRS
loop honest end-to-end: explanations after recall, and a server-side guarantee
that one sitting can't double-update SM-2 no matter what the client does.
After this batch, 3 of 4 dark endpoint groups are lit — only ASA-7
(open-response grading UI) remains as a future batch-anchor.

## F. Legacy analysis & improvement opportunities

- **Assignment creation (legacy `core/` + `sphinx/`):** teachers picked an
  existing ProblemSet and a due date — no help choosing *what* to assign; the
  insight (which chapters are weak) lived in a separate analytics page, if
  anywhere. ASA-6 fuses insight and action: the draft *is* the analytics
  conclusion, with rationale text a teacher can read and overrule. Keep:
  teacher final say (approve/dismiss, title/due-date control). Improve:
  selection is AI-targeted at class weaknesses, with provider transparency.
- **Review/feedback loop (legacy grader):** legacy graded and stored marks;
  students saw right/wrong with no explanation. ASA-4 fixed that for
  assignments; ASA-8 extends it to the SRS drill, which legacy never had at
  all (SRS is a modern addition).
- **Robustness:** legacy server-rendered pages failed loudly (500 page).
  The SPA's failure mode is subtler — a failed fetch can *look like* clean
  data. PRs 1–2 finish stamping that out on every AI teacher panel.
