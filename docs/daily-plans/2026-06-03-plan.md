## B. Why this matters

The V2 overhaul (top initiative, `docs/initiatives/2026-design-system-v2.md`) is
"done" only when **every authenticated surface shares one coherent branded
language.** The shell, auth, home, and Student/Teacher dashboards are already on
V2. The pages a parent, an admin, and—above all—a practising student spend the
most time on (assignment detail, SRS drill) are still on the old blue template,
which breaks the "trustworthy + warm" first impression the moment anyone clicks
past the dashboard. Closing these five page-groups is the single biggest jump
toward the initiative's Definition of Done, and each is independently shippable,
so one failure never blocks the rest.

This is **Improve** work, not migration-for-its-own-sake: every page also gets
`ui/` primitives (`Stat`, `SectionHeading`, `EmptyState`, `Card`, `Badge`,
`Input`), real focus-visible/AA accessibility, and `prefers-reduced-motion`
support it doesn't have today.

## F. Legacy analysis & improvement opportunities

These surfaces have **no legacy port to honour** — the legacy Django 1.11 app
rendered server-side templates with a generic Bootstrap/blue theme; there is no
"good legacy UX" to preserve here. The improvement is wholesale: a coherent,
branded, accessible React surface.

- **Parent surfaces:** legacy gave parents almost nothing (a static progress
  table). The modern app already added trend sparklines + insights panels; V2
  makes them *credible at a glance*, which is the whole parent-trust thesis.
- **Assignment / drill:** legacy submitted whole problem sets to the Cabinet
  service for grading with a page reload per action. Modern already improved this
  (debounced auto-save, instant score). V2 makes the practice loop *feel* as good
  as it works — the "unlock on score" motif turns grading into a reward.
- **Admin:** legacy was Django-admin only. The modern self-serve admin is net-new;
  V2 makes it look like part of the product, not a bolted-on CRUD form.
- **Improvement lever for all five:** replace the per-page hand-rolled inputs,
  cards, and status pills with `ui/` primitives so the *next* page costs less —
  the system gets better each session (the initiative's explicit goal).
