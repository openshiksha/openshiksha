## Summary

Promotes **Accessibility — WCAG 2.1 AA** to the active top initiative and ships
its first batch: a **measured, CI-enforced** accessibility contract for the
public surfaces. Three PRs (the planned A11Y-3/A11Y-4 collapsed — see *Findings*):

| PR | Increment | Class |

## Classification

**New** — net-new platform capability. Legacy Django 1.11 had no accessibility
story to port (no ARIA, no contrast discipline, no automated checking).

## What changed

### A11Y-1 — per-route axe baseline (#389)
- New `docs/initiatives/2026-accessibility-wcag-aa.md` (North Star, phased DoD,
  per-route harness contract, ledger).
- Generalized `e2e/a11y.spec.ts` from a single `/design` test into a
  **parameterized route table** over every unauthenticated surface, each emitting
  `axe-report/<route>.json` (CI artifact) with a per-route `gate` flag.

### A11Y-2 — static jsx-a11y gate (#390)
- `eslint-plugin-jsx-a11y` (`flatConfigs.recommended`) wired into the flat ESLint
  config; npm `overrides` pins its stale `eslint` peer to the repo's `^10` so
  `npm ci` resolves without `--legacy-peer-deps`. Dev-only — no bundle impact.
- Fixed the 11 hits it surfaced (lint stays at `--max-warnings 0`): nested-label
  `depth` widened to 3; a clickable `<li>` row became a native `<button>`; a demo
  `<a href="#">` became a `<button>`; two modal backdrops carry a rationale-tagged
  line disable (both already close on Escape).

### A11Y-5 — gate the clean routes + close-out (this PR)
- `e2e/a11y.spec.ts` now also records axe **`incomplete`** results (checks axe
  could not auto-decide, almost all `color-contrast` over an unreadable
  background) so masked risk is visible in the artifact instead of hiding behind
  a zero-violations summary.
- **Gated** (`gate: true`, asserts zero serious/critical violations):
  `/login`, `/register`, `/register/school`, `/register/open`, `/enquire`.
- **Reporting-mode** (`gate: false`): `/` (enabled hero `.btn-brand`) and
  `/design` (deliberate showcase edge cases + widget iframes).
- This change doc, the manual keyboard/SR checklist
  (`docs/a11y/2026-06-19-public-surfaces-manual-checklist.md`), the initiative
  ledger, and STATUS.md (Accessibility = new #1 Active).

## Findings (why A11Y-3 and A11Y-4 collapsed)

The A11Y-1 baseline measured the public surfaces and found them **already
structurally clean**:

| Route | axe `violations` | `incomplete` (color-contrast) |
|---|--:|--:|
| `/login` | 0 | 12 |
| `/register` | 0 | 8 |
| `/register/school` | 0 | 15 |
| `/register/open` | 0 | 14 |
| `/enquire` | 0 | 15 |
| `/` (home) | 0 | 28 |
| `/design` | 2 (`color-contrast`, `label`) | 115 + `frame-title-unique` |

- **A11Y-3 (structural: label/landmark/heading)** — *no remediation needed.* The
  public/auth surfaces report **zero** label/landmark/heading violations; the M6-01
  skip-link + `#main-content` landmark foundation plus the existing form chrome
  already satisfy these rule families. The only structural axe finding anywhere is
  `label` on `/design`, and it lives **inside sandboxed widget iframes** (`#r` range
  inputs) — widget-framework-internal, documented known-noise, not a public-surface
  defect.
- **A11Y-4 (colour-contrast)** — the contrast story is **one systemic finding**,
  deferred pending a design decision (see below). axe surfaced **no determinable
  contrast _violation_** on the public routes; the failures sit in `incomplete`
  (warm-paper/gradient backgrounds axe can't read) and on `/design` where the
  background is plain enough to compute.

### Systemic finding (deferred — needs a brand-shade decision)

**`.btn-brand` — the primary CTA — fails WCAG AA contrast in its enabled state.**
It is `bg-brand-600` (`#FF6F00`) + `text-white` ≈ **2.8 : 1** (AA needs 4.5 : 1
normal / 3 : 1 large). It only escapes axe `violations` on the auth pages because
those CTAs render **disabled** until the form is valid (axe skips disabled
controls); on `/` the enabled hero button's failure lands in `incomplete` because
axe can't read the hero background. `text-brand-600`/`text-brand-700` as body text
on paper fail similarly (~2.8 / ~4.1 : 1).

This is a **product/design decision**, not a mechanical fix: `#FF6F00` is the
documented sole brand anchor ("the only brand colour", `tailwind.config.js`), so
darkening the CTA repaints the hero element on every screen. For reference, a
white-on-orange CTA needs roughly `#C05300` (≈ 4.7 : 1) or `brand-800` `#9E4500`
(≈ 6.1 : 1) to pass — both noticeably mute the vivid orange. **Recommended A11Y-4
(next batch): a design-led brand-shade decision** (darken the button, or reserve
`brand-600` for large/non-text use and adopt a darker on-text shade), then a
mechanical token-usage sweep + gate `/` and the student core-loop surfaces.
