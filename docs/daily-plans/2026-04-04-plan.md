## A. Today's Objective

Activate the AI analytics pipeline end-to-end: connect grading to AI tasks, then surface learning gap recommendations to students and class health insights to teachers.

---

## B. Why This Matters

The AI engine is the platform's biggest competitive differentiator — spaced repetition, learning gap detection, performance prediction, personalized recommendations, and adaptive learning paths. All of it works in isolation, and all of it is dead. No submission has ever triggered an AI task. No student has ever seen a recommendation. No teacher has ever seen a class insight.

Today's work changes that. With one backend change (wiring `grade_submission` → `analyze_student_subject_room`), every future submission automatically populates the entire AI layer. Then two frontend additions surface the results to users. This is the highest-leverage set of changes available right now — all infrastructure is already built.

### Priority 1: Wire AI Pipeline to Grading

**Problem**: `backend/openshiksha/apps/core/tasks.py` — `grade_submission` task ends at:
```python
_update_assignment_aggregates.delay(submission.assignment_id)
update_proficiency.delay(submission.student_id, subject_room.id)
```

There is no call to `analyze_student_subject_room` or `generate_class_insights_for_subject_room`. Every single AI task in `apps/ai/tasks.py` has zero callers from the grading pipeline.

**Fix**: Add two calls at the end of `grade_submission`, after the existing `update_proficiency` call:
```python
# Trigger AI analytics pipeline (learning gaps, recommendations, mastery, learning path)
from openshiksha.apps.ai.tasks import (
    analyze_student_subject_room,
    generate_class_insights_for_subject_room,
)
analyze_student_subject_room.delay(submission.student_id, subject_room.id)
generate_class_insights_for_subject_room.delay(subject_room.id)
```

**Important**: Also trigger `generate_daily_practice_plan` from within `analyze_student_subject_room`. Check if `analyze_student_subject_room` already calls `generate_daily_practice_plan` — it currently calls detect_learning_gaps, update_performance_prediction, refresh_recommendations, update_student_mastery, and rebuild_learning_path, but NOT `generate_daily_practice_plan`. Add it:
```python
# In apps/ai/tasks.py — analyze_student_subject_room
generate_daily_practice_plan.delay(student_id, subject_room_id)
```

**Also check**: `apps/api/urls.py` — confirm the AI router is included at a URL prefix. The AI app has `urls.py` with a router, but it needs to be included in the main API `urls.py`. Check if `/api/ai/` is registered.

**Files to modify:**
- `backend/openshiksha/apps/core/tasks.py` — add `analyze_student_subject_room.delay()` + `generate_class_insights_for_subject_room.delay()` at end of `grade_submission`

## F. Legacy Analysis & Improvement Opportunities

### AI-driven recommendations (new, no legacy equivalent)
- **Legacy did**: Nothing. The original platform had no personalized recommendations. Students were assigned the same problem sets as the rest of the class. The only "personalization" was remedial assignments auto-created for students scoring < 30%.
- **What we add**: Full SM-2 spaced repetition scheduling, learning gap detection, content recommendations ranked by urgency, daily practice plans. This is a step-function improvement in the platform's educational value.
- **How to apply**: The priority ordering (urgent → high → medium → low) should drive both the visual hierarchy in the student panel AND the ordering in the PracticePlan. Ensure the API returns recommendations ordered by priority.

### Class health insights (new, no legacy equivalent)
- **Legacy did**: Nothing. Teachers could only see aggregate scores in the Django admin or via the legacy grade book view. There was no "chapters the class is struggling with" view.
- **What we add**: Chapter-level class health computed from aggregated Tick data. Teachers can see at a glance which topics need more classroom attention. This is the kind of analytics ed-tech platforms charge premium for.
- **How to apply**: Surface as a compact, scannable table (not charts — charts require interaction). Status colors (🔴/🟡/🟢) should be immediately parseable without reading numbers.

### Grading → analytics coupling (architectural improvement)
- **Legacy did**: The legacy grader made HTTP calls to Cabinet and Edge after each submission, synchronously. Fragile — a Cabinet outage blocked grading.
- **How we improve**: Celery task chaining — `grade_submission` triggers async AI tasks. If AI analysis fails, grading still succeeds. AI tasks retry independently. Fully decoupled.
