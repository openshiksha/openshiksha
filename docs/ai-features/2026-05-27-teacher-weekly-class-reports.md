# Teacher AI Assistant — Weekly Class Summary Reports

**Category:** 7 — Teacher AI Assistant
**Date:** 2026-05-27
**Status:** Shipped (backend + teacher dashboard panel)

## Problem it solves

Teachers can already drill into per-chapter class health (`ClassInsight`) and
per-student gaps, but turning that raw data into a sense of "how did my class do
this week, and what should I do next?" is manual and time-consuming. This feature
gives every teacher a short, plain-language weekly narrative per subject room —
participation, overall performance, the chapters to celebrate, the chapters that
need reteaching, and one concrete suggestion for next week — generated by the LLM
from a deterministic statistics snapshot.

## How it works (technical)

1. **Stats snapshot (deterministic).**
   `analytics.compute_weekly_class_stats(subject_room, week_start, week_end)`
   aggregates `Tick` rows in the Mon–Sun window (matched on `created_at` in the
   active timezone) and returns participation, class average, and the top-N
   weakest/strongest chapters (chapters need ≥2 ticks to qualify). It is pure
   computation — no LLM, no side effects — so it is fully testable offline.

2. **Narrative generation (LLM cascade).**
   `llm_client.generate_class_summary(stats, subject_name, standard_number)` reuses
   the existing provider cascade — Anthropic Claude → Google Gemma → local Ollama →
   deterministic stub. The stub composes a usable sentence from the stats, so the
   report is never empty even with no API keys configured.

3. **Persistence (idempotent task).**
   `tasks.generate_weekly_class_report(subject_room_id, week_start_iso=None)` snaps
   the requested date back to its Monday, computes stats, generates the narrative,
   and upserts a `WeeklyClassReport` keyed on `(subject_room, week_start)`. Re-running
   overwrites in place. Defaults to the current week when no date is given. Token
   counts and the model used are recorded for cost visibility.

4. **API (teacher-only).** Registered under `/api/v1/ai/weekly-reports/`:
   - `GET  /weekly-reports/` — reports for the teacher's rooms (`?subject_room=` filter)
   - `GET  /weekly-reports/{id}/` — single report
   - `GET  /weekly-reports/latest/?subject_room=<id>` — most recent report for a room
   - `POST /weekly-reports/generate/` — queue generation `{subject_room_id, week_start?}`

   A teacher can only ever see or generate reports for `SubjectRoom`s they teach.

5. **Frontend.** `WeeklyReportPanel` (collapsible) sits on the `TeacherDashboard`
   under each subject room beside the existing Class Health panel. It fetches the
   latest report via the `useWeeklyReport` hook and offers Generate / Regenerate.

## Models / APIs created

- **Model:** `WeeklyClassReport` (`ai_weekly_class_reports`) — narrative + stats
  snapshot (`total_students`, `active_students`, `ticks_recorded`, `class_avg_score`,
  `struggling_chapters`, `strong_chapters`), `model_used`, token counts; unique on
  `(subject_room, week_start)`; `participation_rate` property.
- **Migration:** `ai/0005_weeklyclassreport.py`
- **Analytics:** `compute_weekly_class_stats`
- **LLM:** `generate_class_summary`, `_build_class_summary_prompt`, `_stub_class_summary`
- **Task:** `generate_weekly_class_report` (+ `_monday_of_week` helper)
- **Serializers:** `WeeklyClassReportSerializer`, `TriggerWeeklyReportSerializer`
- **View:** `WeeklyClassReportViewSet`
- **Admin:** `WeeklyClassReportAdmin`
- **Frontend:** `useWeeklyReport.ts`, `WeeklyReportPanel.tsx`

## User impact

- **Teachers:** A scannable weekly note per class instead of reading tables —
  surfaces what to reteach and what's working, with an actionable next step.
- **Students (indirectly):** Faster, better-targeted teacher intervention.

## Tests

`backend/openshiksha/apps/ai/tests/test_weekly_reports.py` — 31 tests covering the
model (creation, unique constraint, participation rate), analytics (empty window,
populated window, low-tick exclusion), the LLM cascade (stub/Anthropic/Gemma/Ollama
+ prompt builder), the task (default week, Monday-snapping, idempotency), and the
full API surface with teacher-only permission checks. Full project suite: 436
passing, coverage 91.28% (gate 90%).

## How to verify

1. Log in as a teacher with at least one subject room that has graded `Tick` data
   this week.
2. On the dashboard, expand **Weekly AI Summary** under a subject room and click
   **Generate**; after a moment the narrative + stats appear.
3. Or via API: `POST /api/v1/ai/weekly-reports/generate/ {"subject_room_id": <id>}`,
   then `GET /api/v1/ai/weekly-reports/latest/?subject_room=<id>`.

## Future enhancements

- Schedule a Celery beat job to auto-generate every Sunday night for all active rooms.
- Email/notification delivery of the weekly report to teachers.
- Most-improved / at-risk student callouts in the narrative.
- Hindi / regional-language reports (the cascade already supports language prompts).
- Week-over-week trend ("participation up 12% from last week").

## Dependencies

None beyond the existing AI app. Uses `Tick` data and the shared LLM client;
degrades gracefully to the deterministic stub when no LLM provider is configured.
