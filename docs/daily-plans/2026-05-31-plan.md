## D. Concrete implementation plan

**Branch**: rebase `feat/2026-05-30-question-rich-content` onto
`modernization` once #115 merges; then add the environment detection on
top.
**PR target**: `modernization`

### Priority 1 — `RichContent` + environment detection

`frontend_modern/src/shared/ui/RichContent.tsx` already exists on the
local branch. Add:

```ts
// Detect un-delimited LaTeX environments and treat them as block math.
const ENV_RE = /\\begin\{([a-zA-Z*]+)\}[\s\S]*?\\end\{\1\}/g;

// In findMath(): add ENV_RE hits with block=true at higher priority than
// $...$ delimiters so an environment inside a paragraph is rendered as
// one math chunk rather than partial inline matches.
```

Allowlist additions: include `<table>, <thead>, <tbody>, <tr>, <td>, <th>`
so cabinet HTML tables also pass the sanitiser.

Wire-up: identical to the original M7-01 plan
(`docs/daily-plans/2026-05-30-plan.md` Section D Priority 2).

### Priority 2 — Snapshot fixtures from the audit

Pull three real subparts from the DB and snapshot them through
`RichContent`:

- `QuestionSubpart` whose question_text contains `\begin{array}{c|lcr}`
- `QuestionSubpart` whose question_text contains `<div>...\(…\)...</div>`
- `QuestionSubpart` whose solution_text contains `\begin{tabular}`

Each fixture is a real string with the per-student substitution already
applied (so the assertion is on the rendering, not the substitution).

### Priority 3 — `Skeleton` primitive

`shared/ui/Skeleton.tsx` per yesterday's plan, exported from
`ui/index.ts`, used in `AssignmentDetailPage` loading branch. Keep it
tiny — 10 lines.

### Dependencies / blockers

- M7-02 PR #115 needs to merge first (the import → DB has the correct
  tokens now; the renderer is rendering against the new strings).
- No backend work today.
- DOMPurify already in `package.json` from the earlier branch.

### What could go wrong

- The `ENV_RE` regex is greedy across nested environments. For Cabinet's
  corpus, environments don't nest, so the non-greedy `[\s\S]*?` with a
  back-reference to the opening name is safe. Add a fuzz test.
- KaTeX needs `\\` (row separator) and `\hline` (no surprises). Verify
  with the Q3 salary-table example from the audit.
