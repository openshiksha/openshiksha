## B. Why this matters

The Cabinet bank is the *entire* real K–12 content of OpenShiksha (679 source
questions, 1734 subparts). Per the initiative audit, the remaining defects are:
281 subparts still render the wrong input widget (per-subpart type ignored),
inline `<img>` references in HTML question bodies are dropped, and a long tail of
cabinet token expressions stay un-substituted with no visibility. Each item below
removes one class of "teacher can't assign this without rewriting it." The audit
command turns the DoD from a one-off manual check into an enforced invariant so
future re-imports can't silently regress.

## D. Concrete implementation plan

### 1. M7-08 — `--report-unknowns` + expression coverage

- **File:** `backend/openshiksha/apps/core/management/commands/import_cabinet_questions.py`
  and the expression helper it calls (`convert_expression` / `safe_eval_expr`,
  currently in the same command module or `core/cabinet_expr.py` — locate via the
  `_SAFE_FUNCS` definition).
- Add `parser.add_argument("--report-unknowns", action="store_true")`.
- When set, parse every token expression in every subpart
  (`question_text`, `options`, `correct_answer`, `solution_text`, `hint_text`),
  walk the AST, and collect every `ast.Name` id that is **not**: a sampled
  variable from `variable_constraints`, an allowlisted constant (`_SAFE_CONSTS`),
  or an allowlisted function (`_SAFE_FUNCS`). Print a sorted
  `name → occurrence-count` table and a total; do **not** write to the DB in this
  mode (early return after the scan).
- Triage the reported names; extend `_SAFE_FUNCS`/`_SAFE_CONSTS` for any that are
  legitimate math helpers (e.g. `gcd`, `lcm`, `factorial`, `degrees`, `radians`,
  `pi`, `e`) — only safe, pure, deterministic callables.
- **Test:** `apps/core/tests/test_cabinet_expr.py` — feed a fixture expression set,
  assert the unknown-name report contains exactly the un-allowlisted names, and
  that after extending the allowlist the report for the known-good fixtures is
  empty.
- **What could go wrong:** don't allowlist anything that can mutate state or do
  I/O. Keep the AST walker rejecting attribute access, calls to non-allowlisted
  names, comprehensions, and dunder names (the existing `safe_eval_expr` guards
  should already do this — reuse them, don't fork the validation).

### 2. M7-06 — Inline-image extraction

- **Importer:** at convert time, scan `question_text`/`solution_text`/`hint_text`
  for `<img ... src="...">`. If `src` is a relative cabinet path (no scheme),
  rewrite it to the `raw.githubusercontent.com/openshiksha/openshiksha-cabinet/...`
  URL using the same base the sibling-image discovery already builds. If `src` is
  already absolute http(s), leave it. Reuse the existing image base-URL constant —
  don't hardcode a second copy.
- **Renderer:** `frontend_modern/src/shared/ui/RichContent.tsx` — confirm the
  DOMPurify config allows `img` with `src`, `alt`, and restricts `src` to
  `http`/`https` (DOMPurify `ALLOWED_URI_REGEXP` or an `afterSanitizeAttributes`
  hook that drops non-http(s) `src`). Add `img` to `ALLOWED_TAGS` if not present.
- **Test (backend):** importer test on a fixture whose HTML body contains a
  relative `<img>` — assert the saved text contains the rewritten absolute URL.
- **Test (frontend):** `RichContent` snapshot/RTL test — a `javascript:` or
  relative `src` is stripped; a valid https `src` survives.
- **What could go wrong:** XSS via crafted `src`/`onerror`. Rely on DOMPurify
  (never `dangerouslySetInnerHTML` raw) and assert the malicious-src test.

### 3a. M7-03a — `QuestionSubpart.subpart_type` (backend)

- **Model:** add `subpart_type = models.CharField(max_length=20,
  choices=QuestionType.choices, blank=True, default="")` on `QuestionSubpart`
  (`backend/openshiksha/apps/core/models.py`). Keep `QuestionType` as the single
  source of the enum.
- **Question summary type:** introduce a `"compound"` sentinel for
  `Question.question_type` when subparts are heterogeneous. Add
  `COMPOUND = "compound", "Compound"` to `QuestionType` and an
  `AlterField` migration mirroring the choices (note migration 0015 already
  enumerates the choices inline — add `compound` there or supersede it).
- **Data migration:** backfill `subpart_type` for existing rows from
  `correct_answer["type"]`; default to the parent `question_type` when absent.
  Recompute each `Question.question_type`: unanimous subpart type → that type,
  else `compound`.
- **Importer:** set `subpart_type` per subpart from the already-computed
  `_question_type` (it currently discards all but `converted[0]`); set the
  question summary to `compound` when the set of subpart types > 1.
- **Serializer:** the student-facing subpart serializer (find it — likely
  `apps/core/serializers.py` or `apps/api/`; the api module path differs from the
  legacy note) must add `subpart_type` to `fields`.
- **Grader:** wherever grading dispatches on `question.question_type`
  (`apps/grader/` or `apps/core/grading*`), dispatch per subpart on
  `subpart.subpart_type`, falling back to the question type when blank.
- **Tests:** re-import fixture → every `subpart_type` non-null; a heterogeneous
  fixture flags `question_type == "compound"`; grader test mixing an MCQ subpart
  and a numeric subpart in one question grades each correctly.
- **What could go wrong:** the backfill must be idempotent and not clobber
  hand-authored questions (only set when blank). Migration must be reversible.

### 3b. M7-03b — Frontend per-subpart widget

- **File:** `frontend_modern/src/features/student/QuestionCard.tsx` (and the
  subpart input it renders). Switch the widget selection to
  `subpart.subpart_type ?? question.question_type` so legacy/hand-authored rows
  (blank subpart_type) still work.
- **Types:** add `subpart_type` to the subpart type in
  `frontend_modern/src/types/index.ts`.
- **Test:** RTL/snapshot — a compound question (subpart A = mcq, subpart B =
  numeric) renders an option list for A and a numeric input for B.
- **Depends on 3a** being merged so the API returns the field.

### 4. `audit_cabinet_fidelity` command + CI guard

- **Command:** `apps/core/management/commands/audit_cabinet_fidelity.py`. Reports,
  over `tags__name__startswith="cabinet:"` questions:
  (a) subparts whose rendered widget would mismatch (post-M7-03 should be 0),
  (b) any `question_text`/`solution_text` containing un-wrapped `\begin{` or
  stray block-level HTML tags, (c) count of `Imported Subject %` / `Imported
  Chapter %` placeholders (DoD requires 0), (d) source-id → Question cardinality
  (every id maps to exactly one). Exit non-zero with `--strict` when any metric is
  out of bounds.
- **Test:** `apps/core/tests/test_cabinet_fidelity_audit.py` — seed a small known
  cabinet fixture and assert the audit reports all-green; mutate one row and
  assert it flags. This is the standing regression guard the DoD calls for.
- **What could go wrong:** keep it fast and read-only; scope queries to cabinet
  tags so it never scans hand-authored content.

## F. Legacy analysis & improvement opportunities

- **Per-subpart type (M7-03):** Legacy Cabinet stored `type` per subpart (1=mcq,
  2=multi_select, 3=numeric, 4=fill_blank) — the modern single `question_type` on
  `Question` was the regression. Restoring per-subpart typing *improves* on the
  flat modern schema while faithfully porting the legacy semantics, and the
  `compound` summary is a new affordance legacy lacked (it had no question-level
  type at all).
- **Inline images (M7-06):** Legacy served images from the Cabinet filesystem
  microservice; modern dropped the service but the importer's sibling-file
  discovery missed authors who embedded `<img>` directly. Rewriting to raw GitHub
  URLs keeps the content self-hosted with no microservice — strictly better.
- **Expression coverage (M7-08):** Legacy `croupier` eval'd arbitrary Python;
  modern's `safe_eval_expr` allowlist is a security improvement. `--report-unknowns`
  makes the allowlist's coverage *observable* instead of failing silently.
