The demo seed command amplifies the value: it lets any developer (or a demo stakeholder) instantly see the full platform working — no manual admin panel setup required.

```python
question_text = models.TextField(
    blank=True,
    default='',

options = models.JSONField(
    null=True,
    blank=True,
    help_text='MCQ choices: [{"key": "A", "text": "..."}, ...]. Null for non-MCQ types.',
)
```

**Migration name**: `add_question_text_and_options_to_questionsubpart`

**Serializer changes** (`apps/api/serializers/core.py`):

1. Add a `QuestionSubpartStudentSerializer` that exposes `question_text` + `options` but **omits** `correct_answer` (security: students must not see the answer before submitting).
2. Wire this serializer into `AssignmentDetailSerializer` when returning question data. The existing `QuestionSubpartSerializer` (with `correct_answer`) stays for admin/teacher use only.
3. Add `prefetch_related('problem_set__questions__subparts__tags')` to the `AssignmentViewSet.retrieve()` to avoid N+1 queries.

**Verify**:
```bash

docker-compose exec backend python manage.py migrate
# GET /api/v1/assignments/{id}/ → subpart object must have question_text, options; must NOT have correct_answer
```

### Priority 2: Student Assignment Detail Page

**Files to create:**

```
frontend_modern/src/features/student/
  AssignmentDetailPage.tsx    — Full page: fetch assignment, render questions, submit
  QuestionCard.tsx            — Per-question component with KaTeX + answer inputs
  useAssignmentDetail.ts      — React Query: GET /api/v1/assignments/:id/
  useSubmission.ts            — Fetch/create/patch submission; submit
```

**Route to add in `App.tsx`**: `/student/assignments/:id` → `<AssignmentDetailPage />`

**Wire up `AssignmentCard.tsx`**: The "Start / Continue / Review" button should `navigate('/student/assignments/' + assignment.id)`.

**`AssignmentDetailPage.tsx` data flow:**
```
1. GET /api/v1/assignments/:id/  →  assignment with nested problem_set → questions → subparts
2. GET /api/v1/submissions/?assignment=:id  →  existing submission (if any)
   → if none: POST /api/v1/submissions/ { assignment: id }
3. Local state: Record<subpartId, string>  initialized from submission.answers
4. On answer change → debounce 2s → PATCH /api/v1/submissions/:id/ { answers, completion }
5. Submit button → confirm dialog → PATCH { submitted_at: new Date().toISOString() }
6. Post-submit: show score or "Grading in progress..."
```

**`QuestionCard.tsx` — KaTeX rendering:**

KaTeX is already in `package.json`. Render `question_text` by:
- Splitting on `$...$` (inline) and `$$...$$` (block) delimiters
- Using `katex.renderToString(expr, { throwOnError: false })` for math segments
- Rendering plain-text segments as-is
- Setting `dangerouslySetInnerHTML` only for KaTeX output (it generates safe SVG/HTML)

**Answer inputs by subpart type** (derive type from `correct_answer.type` or a new `question_type` field):
- `mcq`: Radio group rendering `options` array
- `fill_blank`: `<input type="text" />`
- `numeric`: `<input type="number" />`
- Others: Text input fallback

**Progress header:** "X of Y answered" — drives the auto-save `completion` fraction.

**What could go wrong:**
- `SubmissionViewSet.create()` must set `student = request.user` server-side. Verify this — do not trust client-provided `student` field.
- KaTeX CSS must be imported. Add `import 'katex/dist/katex.min.css'` to `main.tsx` or `QuestionCard.tsx`.
- Assignment detail endpoint must be accessible to students. Verify `IsAuthenticated` permission applies and the assignment is visible to the student (via their enrolled SubjectRoom).

## F. Legacy Analysis & Improvement Opportunities

### The Cabinet Dependency Problem

Legacy OpenShiksha stored all question content exclusively in Cabinet (external service). The modern approach stores content locally in `question_text`/`options` with Cabinet as an optional upstream sync. This is strictly better:

| Aspect | Legacy | Modern (today) |
|--------|--------|----------------|
| Dev without Cabinet | Impossible | Possible — seed command creates real questions |
| Grading | Cabinet only | Local `correct_answer` ✅ |
| Content offline | Not possible | Local cache enables offline/low-bandwidth |
| LaTeX rendering | Cabinet PNG images | KaTeX SVG — scalable, copy-pasteable, accessible |

### Adaptive Learning Engine — Integration Opportunity

The newly merged adaptive engine (`StudentMastery`, `LearningPath`) produces personalised next-chapter recommendations. Once a student starts submitting answers:

1. `grade_submission` task → creates `Tick` records
2. `update_proficiency` task → updates `StudentProficiency`
3. `generate_learning_gap_analysis` task → creates `LearningGap` records
4. `compute_learning_path` task → updates `StudentMastery` + `LearningPath`

The student detail page can surface the next step in their learning path as a "Recommended next" card — with zero additional backend work, since the APIs are already built. This is a quick win after the detail page exists.
