## A. Today's objective

Ship the **web push notification** later-phase of Mobile Shell & PWA-Offline as a
batch of 5 atomic PRs. Today's outcome: a student who has installed OpenShiksha
to their home screen can **opt in to push notifications and receive a due-date
reminder as a native phone notification** — even with the app closed — reusing the
already-shipped service worker (MSO-3) and the already-shipped
`send_due_date_reminders` Celery task. Email reminders already exist; web push is
the channel that actually reaches a phone home-screen install.

## B. Why this matters

- **Closes the named later-phase of the top initiative.** The Mobile Shell doc
  lists exactly two later phases: route-level mobile layouts and *"Push
  notifications: due-date reminders as web push (the email reminder already exists;
  web push is the mobile-native channel)."* Batches 1–2 made the PWA installable
  and offline-write-tolerant; web push is the natural next compounding step — it
  makes the home-screen install *worth keeping* by re-engaging the student.
- **Rides shipped infrastructure, near-zero new surface.** The service worker
  (MSO-3, `vite-plugin-pwa`) already registers in prod; we layer a `push` +
  `notificationclick` handler onto it via `workbox.importScripts` (no strategy
  change). The backend already has `send_due_date_reminders` (core/tasks.py:438),
  `User.email_reminders_opt_out` (core/models.py:72), and localized reminder copy.
  We add a parallel push fan-out, not a new scheduler.
- **Mission-core for the target market.** A K-12 student in India on a budget
  Android phone lives on the home screen, not in email. Push is how an ed-tech PWA
  competes with native apps without an app-store presence.
- **Improves on legacy.** Legacy OpenShiksha had email-only notifications. Web push
  is genuinely new capability the platform never had.

## D. Concrete implementation plan

### MPN-1 — Push subscription model + VAPID config + dep *(New, build first)*

**Backend.**
- Add `pywebpush==2.0.0` (and its transitive `py-vapid`, `http-ecdsa`) to
  `backend/requirements.txt` (anchor near `celery==5.6.3` block).
- New model in `backend/openshiksha/apps/core/models.py`:
  ```python
  class PushSubscription(models.Model):
      user = models.ForeignKey(User, related_name="push_subscriptions", on_delete=models.CASCADE)
      endpoint = models.URLField(max_length=512, unique=True)
      p256dh = models.CharField(max_length=255)   # keys.p256dh
      auth = models.CharField(max_length=255)      # keys.auth
      user_agent = models.CharField(max_length=255, blank=True)
      created_at = models.DateTimeField(auto_now_add=True)
  ```
  `unique=True` on `endpoint` makes re-subscribe idempotent (upsert in MPN-2).
- `makemigrations core` → commit the migration.
- VAPID config in `settings/base.py` (read from env, blank-safe so dev/CI without
  keys simply disables push rather than erroring):
  ```python
  VAPID_PUBLIC_KEY = os.getenv("VAPID_PUBLIC_KEY", "")
  VAPID_PRIVATE_KEY = os.getenv("VAPID_PRIVATE_KEY", "")
  VAPID_ADMIN_EMAIL = os.getenv("VAPID_ADMIN_EMAIL", "admin@openshiksha.org")
  ```
- Register `PushSubscription` in `core/admin.py` (read-only-ish list).
- **Test:** model create + `__str__` + unique-endpoint constraint. **Verify:**
  `pytest apps/core/tests/test_models.py`; migration applies clean.
- **What could go wrong:** `pywebpush` pulls native crypto (`cryptography`) —
  already a Django transitive dep, so no new wheel pain. Keep the migration tiny.

### MPN-2 — Subscribe/unsubscribe API + `send_web_push` helper *(New, depends on MPN-1)*

**Backend.**
- New `apps/core/push.py` with `send_web_push(user, payload: dict) -> int`:
  iterate the user's subscriptions, `webpush(subscription_info, json.dumps(payload),
  vapid_private_key=..., vapid_claims={"sub": "mailto:"+VAPID_ADMIN_EMAIL})`; on
  `WebPushException` with response status `404`/`410`, **delete** that stale
  subscription; return count sent. No-op (return 0) if `VAPID_PRIVATE_KEY` is blank.
- Endpoints (add to `apps/api/urls.py` / a small `PushSubscriptionViewSet` or two
  APIViews, auth required):
  - `GET  /api/v1/push/vapid-public-key/` → `{ "publicKey": VAPID_PUBLIC_KEY }`
    (frontend needs it to subscribe; empty string ⇒ frontend hides the affordance).
  - `POST /api/v1/push/subscribe/` body `{endpoint, keys:{p256dh, auth}}` →
    upsert by `endpoint`, attach to `request.user`. Returns 201/200.
  - `POST /api/v1/push/unsubscribe/` body `{endpoint}` → delete (own rows only).
- **Test:** subscribe creates row & is idempotent on repeat; unsubscribe deletes;
  `send_web_push` prunes on a mocked 410; no-op when key blank. Mock `pywebpush`.
- **Verify:** `pytest apps/core` + a manual `curl` subscribe.
- **What could go wrong:** never let `send_web_push` raise into the reminder task —
  wrap per-subscription so one bad endpoint can't abort the fan-out.

### MPN-3 — Service worker push + notificationclick handler *(New, independent)*

**Frontend.**
- The SW uses the `generateSW` strategy (vite.config.ts:88). **Do not switch to
  injectManifest.** Instead add `workbox.importScripts: ['push-handler.js']` so our
  handler layers on top of the generated precache SW (lowest-risk; preserves all
  MSO-3 behavior).
- New `frontend_modern/public/push-handler.js`:
  ```js
  self.addEventListener('push', (event) => {
    const data = event.data ? event.data.json() : {};
    const title = data.title || 'OpenShiksha';
    event.waitUntil(self.registration.showNotification(title, {
      body: data.body || '',
      icon: '/icons/icon-192.png',
      badge: '/icons/badge-72.png',
      data: { url: data.url || '/' },
      tag: data.tag,
    }));
  });
  self.addEventListener('notificationclick', (event) => {
    event.notification.close();
    const url = event.notification.data?.url || '/';
    event.waitUntil(clients.matchAll({ type: 'window' }).then((cs) => {
      const hit = cs.find((c) => c.url.includes(url));
      return hit ? hit.focus() : clients.openWindow(url);
    }));
  });
  ```
- Reuse the existing 192 icon (MSO-1). Add a small monochrome `badge-72.png` if one
  isn't present (Android status-bar badge); fall back to the 192 if generating one
  is out of scope.
- **Test:** a `check-manifest`-style mjs guard asserting `push-handler.js` exists in
  `public/` and `importScripts` references it in the built SW. **Verify:**
  `npm run build`; confirm the entry chunk is unchanged vs the 160 kB guard (the
  handler is a separate precached file, not in the entry chunk).
- **What could go wrong:** `importScripts` path must be root-relative; confirm the
  built `sw.js` contains the import. Devtools `enabled:false` means no SW in dev —
  test push in a prod build/preview.

### MPN-4 — Frontend opt-in + settings toggle *(New, depends on MPN-2 + MPN-3)*

**Frontend.**
- `frontend_modern/src/features/pwa/usePushSubscription.ts`: exposes
  `{ supported, permission, isSubscribed, subscribe(), unsubscribe() }`.
  `subscribe()` → `Notification.requestPermission()` →
  `registration.pushManager.subscribe({ userVisibleOnly: true,
  applicationServerKey: urlBase64ToUint8Array(publicKey) })` (publicKey from
  `GET /push/vapid-public-key/`; if blank ⇒ `supported=false`) → POST the
  serialized subscription to `/push/subscribe/`. `unsubscribe()` mirrors.
- Affordance: a dismissible, localized "Get reminders on your phone" card/button —
  reuse the `InstallBanner`/`OfflineBanner` pattern (MSO-2/5) and place it on the
  student dashboard and/or `ProfilePage`. Only render when `supported && permission
  !== 'denied' && !isSubscribed`.
- `ProfilePage` (`features/shared/ProfilePage.tsx`): add a **Push notifications**
  toggle next to the existing email-reminders control; on/off calls
  subscribe/unsubscribe.
- i18n: new `push.*` keys (enable CTA, enabled confirmation, blocked-in-browser
  hint) in en/hi/mr via the LA registry. Follow the `pwa.install*` precedent.
- **Test:** Vitest — hook hides when unsupported / key blank; subscribe posts the
  serialized payload; toggle reflects state. Mock `navigator.serviceWorker` +
  `PushManager`.
- **What could go wrong:** iOS Safari only supports web push for **installed**
  PWAs (16.4+) — gate the affordance on `supported` and degrade gracefully; don't
  promise what a given browser can't do (Principle 4: honest UX).

## F. Legacy analysis & improvement opportunities

- **Notifications:** Legacy OpenShiksha had **email-only** notifications (grading
  complete / remedial assigned). It had no push channel of any kind — there was no
  PWA, no service worker, no installable shell. Web push is **net-new capability**,
  not a port. The improvement: meet students where they actually are (home screen),
  with a channel that survives the app being closed and doesn't depend on them
  opening an inbox.
- **What to preserve:** the reminder *cadence* and *eligibility* logic
  (`send_due_date_reminders`, 24h window, opt-out respect) is sound — push reuses it
  rather than re-deriving "who/when," so the two channels can never drift.
